Introduction to JavaScript

The language of the web — a dynamic, garbage-collected, single-threaded language with first-class functions, now running everywhere from browsers to servers to phones.

JavaScript — a high-level, dynamically typed, multi-paradigm language (procedural, object-oriented via prototypes, functional). Its official specification is ECMAScript (ECMA-262); a new edition ships every June.

Why JavaScript?

The only language browsers run natively

HTML gives structure, CSS gives style, JavaScript gives behaviour. (WebAssembly runs alongside it, but JS is the glue.)

Runs everywhere

Servers (Node.js, Deno, Bun), mobile (React Native), desktop (Electron), edge functions, databases (MongoDB shell).

First-class functions

Functions are values: pass them, return them, store them. Closures make callbacks and modules natural.

Asynchronous by design

A single thread plus an event loop handles thousands of concurrent I/O operations without blocking.

How JavaScript Runs

Source text → tokens → AST → bytecode → optimised machine code. One call stack, one heap, and an event loop that feeds it work.

The pipeline inside V8
Source code

→

→
TurboFan (optimised machine code)
1
Parse
The source is tokenised and turned into an Abstract Syntax Tree. Syntax errors are found here — before a single line runs.
2
Interpret
The Ignition interpreter compiles the AST to compact bytecode and starts running it immediately (fast startup).
3
Profile
While running, the engine records which functions are hot and which types they see.
4
Optimise (JIT)
Hot functions are compiled by TurboFan (and the mid-tier Maglev) into machine code specialised for the observed types.
5
Deoptimise
If an assumption breaks (a function that always saw numbers suddenly gets a string), the engine throws the optimised code away and falls back to bytecode.

JIT (Just-In-Time) compilation — compiling code to machine code while the program runs, using runtime type feedback — so JavaScript is neither purely interpreted nor ahead-of-time compiled.

Performance tip

Write monomorphic code: keep the same object shapes and argument types in hot paths. Mixing types in one function (add(1, 2) then add('a', 'b')) makes it polymorphic and slower.

Memory: stack and heap

Call stack

A LIFO stack of execution contexts — one frame per running function call, holding its local variables and where to return to.

Heap

A large unstructured region where objects, arrays and closures live. Managed automatically by the garbage collector.

Execution contexts

Every time code runs it gets an execution context. There is one global context, plus one new context per function call. Each context is created in two phases:

Creation (memory)Scope is set up; var names are created as undefined, function declarations are stored in full, let/const/class names are created but uninitialised (TDZ). this is determined.
ExecutionCode runs line by line; assignments fill in the values.

Single-threaded, yet non-blocking

JavaScript runs your code on one thread. Slow work (network, disk, timers) is handed to the runtime; when it finishes, a callback is queued and the event loop pushes it onto the stack once the stack is empty. See The Event Loop topic for the full picture.

Is JavaScript interpreted or compiled?

Both. Modern engines parse to bytecode and interpret it for fast startup, then JIT-compile hot functions to optimised machine code using runtime type feedback — and can deoptimise if assumptions break.

What is an execution context?

The environment a piece of code runs in: its variable environment (scope), the outer-scope reference (scope chain), and the value of this. A global context is created first, then one per function call, pushed onto the call stack.

Hoisting and the Temporal Dead Zone

Temporal Dead Zone (TDZ) — the period from the start of a block until a let/const/class declaration is evaluated. Touching the name in that window throws a ReferenceError.

JavaScript
console.log(x);        // var is hoisted and set to undefined
var x = 5;

try {
  console.log(y);      // y exists but is in the TDZ
} catch (e) {
  console.log(e.name + ": " + e.message);
}
let y = 10;
Output
undefined
ReferenceError: Cannot access 'y' before initialization

The TDZ is temporal (about time, not position): a function that reads the variable is fine as long as it is called after the declaration runs.

JavaScript
function read() { return value; }  // refers to value declared below
let value = 42;
console.log(read());               // called after initialisation → OK
Output
42
The classic loop bug
JavaScript
const withVar = [];
for (var i = 0; i < 3; i++) withVar.push(() => i);
console.log(withVar.map((f) => f()));

const withLet = [];
for (let j = 0; j < 3; j++) withLet.push(() => j);
console.log(withLet.map((f) => f()));
Output
[ 3, 3, 3 ]
[ 0, 1, 2 ]

var i is one variable shared by every closure (it is 3 when they run). let j creates a fresh binding per iteration, so each closure captures its own value.

Naming rules
  • Letters, digits, _ and $; cannot start with a digit; case-sensitive (name ≠ Name).
  • Reserved words (class, return, new…) cannot be names.
  • Conventions: camelCase for variables/functions, PascalCase for classes, UPPER_SNAKE_CASE for true constants.
Do

Default to const; switch to let only when the variable is reassigned. It documents intent and prevents accidental reassignment.

Avoid

var in new code, and undeclared assignments like total = 0 (creates an accidental global in sloppy mode, throws in strict mode).

What is the difference between var, let and const?

var is function-scoped, hoisted with value undefined, and can be re-declared. let and const are block-scoped and hoisted into the TDZ (accessing them before the declaration throws). const additionally forbids reassignment of the binding — but the object it points to can still be mutated.

Are let and const hoisted?

Yes — their names are created when the scope is entered (that is why they shadow outer variables from the start of the block), but they are not initialised, so any access before the declaration line throws a ReferenceError. That window is the temporal dead zone.

How many data types does JavaScript have?

Eight: seven primitives (number, bigint, string, boolean, undefined, null, symbol) and object. Arrays, functions, dates and maps are all objects.

Why does typeof null return "object"?

In the first implementation values carried a type tag, and the tag for objects was 0; null was the null pointer (all zeros), so it read as an object. Fixing it would break the web, so it stays.

Autoboxing

Methods on primitives work because of autoboxing: "hi".length briefly wraps the string in a String object, reads the property, and discards the wrapper.

Watch out

Is JavaScript pass-by-reference?

No. It is always pass-by-value; for objects the value is a reference (sometimes called call by sharing). Mutating through the parameter is visible to the caller, but reassigning the parameter is not.

What is the difference between == and ===?

=== compares without type conversion (and objects by identity). == first coerces operands to a common type using the abstract equality rules — null == undefined, booleans and strings become numbers, objects become primitives. Prefer ===; x == null is the common exception.

What does [] + {} evaluate to?

"[object Object]". Both are converted to primitives: [] → "", {} → "[object Object]", and + with a string concatenates. (Typed at the start of a line in a console, {} may be parsed as an empty block, which is why {} + [] can show 0.)

Why is 0.1 + 0.2 !== 0.3?

Numbers are IEEE 754 binary doubles; 0.1 and 0.2 cannot be represented exactly, so their sum is 0.30000000000000004. Compare with a tolerance (Math.abs(a - b) < Number.EPSILON) or work in integers.

What is Number.MAX_SAFE_INTEGER?

2^53 − 1 (9007199254740991) — the largest integer where every integer below it is exactly representable. Beyond it, n + 1 may equal n; use BigInt.

What is the difference between a function declaration and a function expression?

A declaration (function f() {}) is a statement that is hoisted with its body, so it can be called before it appears. An expression creates the function as a value (assigned to a variable, passed as an argument); it only exists once that line runs.

A closure keeps its whole environment reachable. A long-lived closure (event listener, interval, cache) that references a big object keeps that object in memory — a common leak.

What is a closure? Give a practical use.

A function together with references to the variables of the scope it was defined in; it can read and update them even after the outer function returned. Why does the var loop print 4, 4, 4?

var is function-scoped, so all three callbacks close over the same i. The callbacks run after the loop finished, when i is 4. let creates a new binding for each iteration, so each callback gets its own value.

How is the value of this determined?

By the call site, in priority order: new → the new object; call/apply/bind → the given object; method call obj.f() → obj; plain call → undefined (strict) or the global object (sloppy). Arrow functions have no own this and use the enclosing scope's.

Why does passing obj.method as a callback lose this?

Passing obj.method passes only the function value; the callback is later invoked as a plain call with no object before the dot, so this becomes undefined. Fix with an arrow wrapper () => obj.method(), obj.method.bind(obj), or class fields with arrow functions.

What is the difference between Object.freeze and const?

const prevents reassigning the variable; the object stays mutable. Object.freeze makes the object's own properties read-only and non-extensible — but only one level deep, and it says nothing about the variable.

seal vs freeze?

Both prevent adding and deleting properties. seal still allows changing existing values; freeze also makes every existing data property read-only.

Explain prototypal inheritance.

Each object has an internal [[Prototype]] link to another object. When a property is not found on the object, the engine looks it up on the prototype, then that object's prototype, and so on until null. Methods are shared this way; classes are syntax over the same mechanism.

What is the difference between __proto__ and prototype?

__proto__ (really [[Prototype]]) is the link on every object to what it inherits from. prototype is a property on constructor functions/classes: the object that becomes the [[Prototype]] of instances created with new.

Composition over inheritance

Deep hierarchies are brittle. Often it is simpler to compose behaviours: build objects from small functions or mixins.

Why must super() be called before this in a derived constructor?

In a derived class the parent constructor is responsible for creating the object. Until super() runs there is no this to use, so accessing it throws a ReferenceError.

Does JavaScript support multiple inheritance?

No — an object has exactly one prototype. You get similar results with mixins (functions that take a class and return an extended class), Object.assign of method objects, or composition.

What is the difference between a generator and a normal function?

A normal function runs to completion when called. A generator function returns an iterator immediately without running; each next() runs it until the next yield, keeping its local state between calls. That makes it ideal for lazy sequences, custom iterators and (historically) async flow control.

Asynchronous JavaScript

The Event Loop

One thread, one call stack — and a loop that, whenever the stack is empty, drains all microtasks and then takes the next macrotask. Predicting output order is a top interview skill.

The moving parts

Call stack

Where synchronous code runs, one frame at a time. Nothing else runs until it is empty.

Web / runtime APIs

Timers, network, file I/O, DOM events — handled outside the JS thread by the browser or libuv (Node).

Macrotask (task) queue

setTimeout, setInterval, setImmediate, I/O callbacks, UI events, MessageChannel.

Microtask queue

Promise reactions (then/catch/finally, code after await), queueMicrotask, MutationObserver. Node's process.nextTick has its own even-higher-priority queue.

One turn of the loop
1
Run a task
Take the oldest macrotask (the initial script is the first) and run it to completion.
2
Drain microtasks
Run every microtask — including ones queued while draining — until the queue is empty.
3
Render (browsers)
If it's time for a frame: requestAnimationFrame callbacks, style, layout, paint.
4
Repeat
Pick the next macrotask.
Predict the output

A setTimeout(fn, 0) never runs before microtasks queued in the same task. 0 means “as soon as possible after at least 0 ms”, not “now”.

ESM subtlety

At the top level of an ES module the module body itself runs as part of a promise job, so there a .then callback can run before a process.nextTick — one reason not to depend on nextTick-vs-promise ordering.

What is the difference between microtasks and macrotasks?

Macrotasks (timers, I/O, events) are taken one per loop turn. Microtasks (promise reactions, queueMicrotask) run right after the current task and the whole queue is drained before the next macrotask or render. So promise callbacks always beat a setTimeout(…, 0) scheduled at the same time.

If JavaScript is single-threaded, how does it do async work?

The engine is single-threaded, but the runtime is not: timers, network and disk I/O run in the browser or libuv thread pool. When they finish, their callbacks are queued, and the event loop runs them on the main thread when the call stack is empty.

What are the states of a Promise?

Pending, fulfilled and rejected. Fulfilled and rejected are together called settled; a settled promise is immutable, and handlers attached later still run (asynchronously) with the settled value.

Why do promise callbacks run asynchronously even if the promise is already resolved?

Handlers are always queued as microtasks, never called synchronously. This guarantees consistent ordering — code after .then(...) always runs before the handler, whether the promise was already settled or not.

Promise.all vs Promise.allSettled?

all fails fast: it rejects with the first error and you lose the other results. allSettled always waits for every promise and reports each outcome, so use it when partial success is acceptable (e.g. sending many notifications).

race vs any?

race settles with the first promise to settle, success or failure. any ignores rejections and fulfils with the first success; it rejects only if all reject (with an AggregateError).

What does an async function return?

Always a Promise. A returned value resolves it; a thrown error rejects it; a returned promise is adopted.

Does await block the thread?

No. It suspends only the current async function; the rest of the function becomes a microtask continuation, and the event loop keeps running other code meanwhile.

It only queues a macrotask. It runs after the current synchronous code, after all microtasks, and after any earlier timers — and browsers may clamp the delay.

  • require(esm) is supported in modern Node (22+) for ES modules without top-level await.
What are the main differences between CommonJS and ES modules?

ESM uses static import/export, is analysed before execution (enabling tree-shaking and top-level await), exports live read-only bindings and is always strict. CJS uses synchronous runtime require, exports a plain object (copied values), and has __dirname/module.

  };

function memoize(fn, keyFn = (...args) => JSON.stringify(args)) {
  const cache = new Map();

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

Debounce & Throttle

Two ways to rate-limit a function that fires too often (typing, scrolling, resizing): debounce waits for quiet, throttle runs at most once per interval.

Debounce

Run only after the calls have stopped for wait ms. Every new call resets the timer. → search-as-you-type, auto-save, resize end.

Throttle

Run at most once every wait ms, no matter how often it is called. → scroll position, mouse move, rate-limited APIs.

Debounce
JavaScript
function debounce(fn, wait) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), wait);
  };
}

const search = debounce((q) => console.log("searching for:", q), 30);
search("j");
search("ja");
search("jav");                          // only this one survives the burst
setTimeout(() => search("javascript"), 60);
Output
searching for: jav
searching for: javascript
Throttle
JavaScript
function throttle(fn, wait) {
  let last = 0, timer = null, pendingArgs = null;
  return function (...args) {
    const now = Date.now();
    const remaining = wait - (now - last);
    if (remaining <= 0) {               // leading call
      last = now;
      fn.apply(this, args);
    } else {                            // remember the latest call for the trailing edge
      pendingArgs = args;
      timer ??= setTimeout(() => {
        last = Date.now();
        timer = null;
        fn.apply(this, pendingArgs);
      }, remaining);
    }
  };
}

const onScroll = throttle((y) => console.log("handle scroll at", y), 50);
onScroll(0);                  // runs immediately (leading edge)
onScroll(10);                 // ignored…
onScroll(20);                 // …but the latest is kept for the trailing edge
Output
handle scroll at 0
handle scroll at 20

Key point

Debounce vs throttle?

Debounce delays execution until calls stop for a quiet period (only the last call runs). Throttle lets a call through at most once per interval, spreading executions evenly while calls continue.

Garbage Collection & Memory Leaks

JavaScript frees memory automatically once objects become unreachable. Leaks happen when you accidentally keep them reachable.

Reachability

The collector starts from roots — globals, the current call stack, active closures, pending callbacks — and marks everything reachable from them. Anything not marked is garbage, even if it points to other garbage (so cycles are fine).

1
Mark
Traverse from the roots and mark every reachable object.
2
Sweep / compact
Reclaim unmarked memory; optionally move live objects together.

Young generation

New objects are allocated here. Most die young, so it is collected often and cheaply (scavenge).

Old generation

Objects that survive a few collections are promoted. Collected less often with incremental / concurrent mark-sweep-compact.

Key point

V8's collector (Orinoco) is generational, incremental and mostly concurrent, keeping pauses short. You cannot trigger GC from normal code (node --expose-gc gives global.gc() for experiments).

How does garbage collection work in JavaScript?

Engines use tracing mark-and-sweep: starting from roots (globals, stack, closures) they mark reachable objects and reclaim the rest. V8 is generational — frequent cheap collection of the young generation, rarer mark-compact of the old — and does much of the work incrementally and concurrently.

Can circular references cause memory leaks?

Not with mark-and-sweep: a cycle that is unreachable from the roots is collected. (They did leak with old reference-counting collectors, e.g. IE6 DOM/JS cycles.)

No. fetch rejects only on network errors (DNS failure, offline, CORS block, abort). Any HTTP response — including 404 and 500 — fulfils; check response.ok or response.status and throw yourself.

localStorage persists across sessions, sessionStorage lasts for one tab session; both are ~5 MB, string-only, synchronous and never sent to the server. Cookies are tiny, sent with every matching request, and can be HttpOnly (hidden from JS) — the right place for session identifiers.

Back-pressure: when the consumer is slower than the producer, pipeline/pipe pause the source so memory stays bounded — the reason to stream a 10 GB file instead of readFile-ing it.

Why use streams instead of reading a whole file?

Streams process data chunk by chunk, so memory use stays constant regardless of size, work starts before all data arrives, and back-pressure keeps fast producers from overwhelming slow consumers.

function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const items = [...iterable];
    const results = new Array(items.length);
    let remaining = items.length;
    if (remaining === 0) return resolve(results);
    items.forEach((item, i) => {
      Promise.resolve(item).then((value) => {
        results[i] = value;                 // keep INPUT order, not finish order
        if (--remaining === 0) resolve(results);
      }, reject);                           // first rejection wins
    });
  });
}

function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== "object") return value;
  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);
  if (seen.has(value)) return seen.get(value);            // handle cycles
  if (value instanceof Map) {
    const m = new Map(); seen.set(value, m);
    value.forEach((v, k) => m.set(deepClone(k, seen), deepClone(v, seen)));
    return m;
  }
  const copy = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  seen.set(value, copy);
  for (const key of Reflect.ownKeys(value)) copy[key] = deepClone(value[key], seen);
  return copy;
}
function deepEqual(a, b) {
  if (Object.is(a, b)) return true;
  if (typeof a !== "object" || typeof b !== "object" || !a || !b) return false;
  if (Object.getPrototypeOf(a) !== Object.getPrototypeOf(b)) return false;
  const ka = Reflect.ownKeys(a), kb = Reflect.ownKeys(b);
  return ka.length === kb.length && ka.every((k) => deepEqual(a[k], b[k]));
}

class Emitter {
  #events = new Map();
  on(name, fn) {
    (this.#events.get(name) ?? this.#events.set(name, []).get(name)).push(fn);
    return () => this.off(name, fn);        // return an unsubscribe function
  }
  off(name, fn) {
    this.#events.set(name, (this.#events.get(name) ?? []).filter((f) => f !== fn && f.original !== fn));
  }
  once(name, fn) {
    const wrapper = (...args) => { this.off(name, wrapper); fn(...args); };
    wrapper.original = fn;
    return this.on(name, wrapper);
  }
  emit(name, ...args) {
    const list = [...(this.#events.get(name) ?? [])];   // copy: listeners may unsubscribe
    list.forEach((fn) => fn(...args));
    return list.length > 0;
  }
}

  if (a.length !== b.length) return false;

const longestUniqueSubstring = (s) => {        // sliding window, O(n)
  let best = 0, start = 0;

    lastSeen.set(ch, i);
    best = Math.max(best, i - start + 1);
  });
  return best;
};

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

async function retry(fn, { retries = 3, delay = 5 } = {}) {
  for (let attempt = 1; ; attempt++) {
    try {
      return await fn(attempt);
    } catch (err) {
      if (attempt > retries) throw err;
      await sleep(delay * 2 ** (attempt - 1));     // exponential back-off
    }
  }
}

async function mapWithConcurrency(items, limit, fn) {
  const results = new Array(items.length);
  let next = 0, active = 0, peak = 0;
  async function worker() {
    while (next < items.length) {
      const i = next++;
      peak = Math.max(peak, ++active);
      results[i] = await fn(items[i]);
      active--;
    }
  }
  await Promise.all(Array.from({ length: limit }, worker));
  return { results, peak };
}

A tiny LRU cache
JavaScript
class LRUCache {
  #map = new Map();                       // Map remembers insertion order
  constructor(capacity) { this.capacity = capacity; }
  get(key) {
    if (!this.#map.has(key)) return -1;
    const value = this.#map.get(key);
    this.#map.delete(key);                // move to most-recent position
    this.#map.set(key, value);
    return value;
  }
  put(key, value) {
    this.#map.delete(key);
    this.#map.set(key, value);
    if (this.#map.size > this.capacity) {
      this.#map.delete(this.#map.keys().next().value);   // evict least recent
    }
  }
  keys() { return [...this.#map.keys()]; }
}
const lru = new LRUCache(2);
lru.put("a", 1);
lru.put("b", 2);
lru.get("a");
lru.put("c", 3);                          // evicts "b"
console.log(lru.keys(), lru.get("b"), lru.get("c"));
Output
[ 'a', 'c' ] -1 3
Key point

Talk through complexity as you go: the anagram and two-sum solutions are O(n) time / O(n) space; the LRU operations are O(1) because Map keeps insertion order.

Interview Prep

JavaScript Interview Q&A

Rapid-fire questions from junior to senior level. Expand each for a crisp, interview-ready answer; follow the topic links in your head to go deeper.

Fundamentals
What are the data types in JavaScript?

Seven primitives — number, bigint, string, boolean, undefined, null, symbol — and object (which includes arrays, functions, dates, maps…). Primitives are immutable and compared by value; objects are compared by reference.

var vs let vs const?

var: function scope, hoisted as undefined, re-declarable. let: block scope, TDZ, reassignable. const: block scope, TDZ, no reassignment (object contents still mutable).

What is the temporal dead zone?

The span between entering a scope and the line where a let/const/class is declared. The binding exists (it is hoisted) but is uninitialised; any access throws ReferenceError.

null vs undefined?

undefined means a value was never assigned (missing variable value, property, argument or return). null is an explicit “empty” set by the programmer. null == undefined is true, === is false, typeof null is "object".

== vs ===?

=== compares type and value with no conversion. == coerces operands first (e.g. '1' == 1). Use ===, except x == null to test for null-or-undefined.

What is NaN and how do you test for it?

“Not a Number”, a number value produced by invalid maths (0/0, Number('x')). It is not equal to itself, so use Number.isNaN(x) or Object.is(x, NaN).

Functions & scope
What is a closure?

A function plus the lexical environment it was created in. Inner functions keep access to outer variables after the outer function returns — used for private state, factories, memoization, and callbacks.

What is hoisting?

Declarations are processed before code runs: function declarations are fully available, vars are undefined, let/const/class sit in the TDZ.

Explain this in JavaScript.

Determined at call time: new → new object; call/apply/bind → given object; obj.fn() → obj; plain call → undefined (strict) or global (sloppy). Arrow functions inherit this lexically.

call vs apply vs bind?

call(this, a, b) and apply(this, [a, b]) invoke immediately; bind(this, a) returns a new permanently bound function.

Arrow functions vs regular functions?

Arrows have lexical this and arguments, cannot be constructors, have no prototype, and are always expressions. Regular functions get a dynamic this and can be used with new.

What are higher-order functions?

Functions that take functions as arguments or return functions — map, filter, reduce, setTimeout, decorators like debounce and memoize.

Currying vs partial application?

Currying turns an n-ary function into n unary functions f(a)(b)(c). Partial application fixes some arguments and returns a function taking the rest (bind, partial).

Objects & prototypes
How does prototypal inheritance work?

Every object links to a prototype. Missing properties are looked up along the chain until null. class/extends builds these chains; methods are shared through Class.prototype.

What does the new keyword do?

Creates an object, links it to Ctor.prototype, runs the constructor with this bound to it, and returns it (unless the constructor returns another object).

How do you deep-copy an object?

structuredClone(obj) (handles Dates, Maps, Sets, cycles; not functions or class prototypes). JSON.parse(JSON.stringify(obj)) only for JSON-safe data. Spread and Object.assign are shallow.

Object.freeze vs Object.seal?

Both stop adding/removing properties; freeze also makes values read-only. Both are shallow.

Map vs Object, Set vs Array?

Map: any key type, insertion order, size, fast frequent updates, no prototype keys. Set: unique values with O(1) has, versus an array's O(n) includes.

What are WeakMap and WeakSet for?

Associating data with objects without preventing their garbage collection — private data, caches, “visited” marks. Keys must be objects; they are not iterable.

Asynchronous JavaScript
Explain the event loop.

JS runs on one call stack. Async work is delegated to the runtime; completions queue callbacks. When the stack is empty the loop drains all microtasks (promise reactions), then runs the next macrotask (timer, I/O, event), and in browsers may render between tasks.

Microtask vs macrotask?

Microtasks: promise then/catch/finally, await continuations, queueMicrotask — all run right after the current task. Macrotasks: setTimeout, setInterval, I/O, UI events — one per loop turn. Hence Promise.then runs before setTimeout(…, 0).

What is a Promise?

An object representing the eventual result of an async operation; pending → fulfilled/rejected, settled once. then returns a new promise, enabling chaining and centralised error handling with catch.

Promise.all vs allSettled vs race vs any?

all: all fulfil or first rejection. allSettled: waits for all, reports each. race: first to settle. any: first to fulfil, AggregateError if all reject.

How does async/await relate to promises?

Syntax sugar: an async function returns a promise; await pauses that function until a promise settles, resuming with its value or throwing its reason, so try/catch works.

How do you run async tasks in parallel vs in sequence?

Parallel: start them all, then await Promise.all([...]). Sequence: for…of with await inside. Never forEach with an async callback.

How do you cancel a fetch or other async work?

Pass an AbortController's signal to fetch (or your own function), then call controller.abort(). AbortSignal.timeout(ms) gives a ready-made timeout signal.

Browser & performance
What is event delegation?

One listener on a parent handles events from many children via bubbling and event.target.closest(...) — fewer listeners and it works for elements added later.

Event bubbling vs capturing?

Events travel from window down to the target (capture), then back up (bubble). Listeners run in the bubble phase unless registered with { capture: true }. stopPropagation() halts the journey.

Debounce vs throttle?

Debounce runs once after activity stops for N ms (search input). Throttle runs at most once every N ms during activity (scroll).

What causes memory leaks in JavaScript?

Anything that keeps unused objects reachable: uncleared intervals, listeners never removed, unbounded caches, closures holding big data, detached DOM nodes referenced from JS, accidental globals.

localStorage vs sessionStorage vs cookies?

localStorage persists, sessionStorage is per-tab; both ~5 MB, JS-only. Cookies are small, sent with requests, and can be HttpOnly — use them for auth.

What is CORS?

A browser mechanism that lets servers opt in to cross-origin reads via Access-Control-Allow-* headers, with preflight OPTIONS requests for non-simple requests. It protects users; it is enforced by browsers, not servers.

Modules, tooling & modern JS
ES modules vs CommonJS?

ESM: static import/export, live bindings, async loading, top-level await, strict by default, tree-shakable. CJS: runtime require, module.exports object, synchronous, Node-specific.

What is strict mode?

A safer JS variant: undeclared assignments throw, this is undefined in plain calls, silent failures become errors, with is banned. Automatic in modules and classes.

What is a polyfill vs a transpiler?

A polyfill adds a missing built-in API at runtime (e.g. Array.prototype.flat). A transpiler (Babel, TypeScript) rewrites new syntax into older syntax at build time.

Why use TypeScript?

Static types catch errors at compile time, power editor autocompletion and safe refactoring, and document intent. It compiles to plain JavaScript; types disappear at runtime.

What are generators used for?

Functions that can pause with yield — lazy/infinite sequences, custom iterators, two-way coroutines, and (async generators) streaming data such as paginated APIs.

What is a Proxy?

A wrapper that intercepts operations (get, set, has, delete, apply…) on a target object — used for validation, reactivity (Vue 3), logging and virtual properties. Reflect supplies the default behaviour.
