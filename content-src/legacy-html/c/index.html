Introduction to C

A small, fast, portable systems language — the language of operating systems, embedded devices, databases and the runtimes of most other languages.

C — a statically typed, compiled, procedural language that gives you direct access to memory through pointers and maps closely to what the hardware actually does. It trusts the programmer: there is no garbage collector, no bounds checking and no exceptions.

Close to the machine

You see memory, addresses and bytes. Understanding C explains how every higher-level language works underneath.

Everywhere

Fast & small

No runtime or VM; a C binary is just machine code. Predictable performance and tiny footprint.

Portable

A C compiler exists for practically every CPU ever made. The standard library is small and everywhere.

Syntax basics

C is case-sensitive, every statement ends with ;, and blocks are delimited by { }. Whitespace and indentation don’t matter to the compiler.

Is C a high-level or low-level language?

It is usually called a middle-level language: it has high-level constructs (functions, loops, structs, types) but also low-level access (pointers, bit manipulation, manual memory) that maps almost one-to-one onto machine instructions.

What is the difference between C and C++?

C++ started as “C with classes” and is (almost) a superset of C. It adds classes, templates, references, RAII, exceptions, namespaces and a large standard library (STL). C stays small and procedural. Some valid C is not valid C++ (e.g. implicit void * conversion from malloc, designated-initializer order, int new;).

The Compilation Model

Turning main.c into an executable is four separate stages: preprocess → compile → assemble → link. Knowing them makes compiler and linker errors easy to read.

main.c
→
Preprocessor → main.i
→
Compiler → main.s
→
Assembler → main.o
→
Linker → a.out
The four stages
1
Preprocessing (cpp)
Text substitution: expands #include (pastes header files in), #define macros, #if conditionals, strips comments. Output: one big translation unit (-E).
2
Compilation (cc1)
Parses the C, type-checks it, optimises it and emits assembly for the target CPU (-S). Syntax and type errors happen here.
3
Assembly (as)
Converts assembly into machine code in an object file (.o) with a symbol table — unresolved references to functions defined elsewhere are left as holes (-c).
4
Linking (ld)
Combines object files and libraries (libc, -lm…), resolves every symbol to an address, and writes the executable. “undefined reference” errors happen here.
Terminal
$ gcc -E main.c -o main.i      # stop after preprocessing
$ gcc -S main.c -o main.s      # stop after compiling (assembly)
$ gcc -c main.c -o main.o      # stop after assembling (object file)
$ gcc main.o util.o -o app     # link object files into an executable
$ gcc -save-temps main.c       # keep main.i, main.s, main.o all at once
$ nm main.o                    # list symbols (U = undefined, T = defined text)

What is a translation unit?

One .c file after preprocessing — the source plus every header it includes, with macros expanded. The compiler works on one translation unit at a time; the linker joins them.

What is the difference between a compiler error and a linker error?

A compiler error means a single file is not valid C (syntax, types, undeclared names). A linker error means every file compiled fine, but a symbol that was declared and used was never defined in any object file or library (or was defined twice).

Static vs dynamic linking?

Static linking copies library code into the executable (.a archives) — bigger binary, no runtime dependency. Dynamic linking (.so / .dylib / .dll) records a reference that the loader resolves when the program starts — smaller binaries, shared updates, but the library must be present.

Program Structure & main

A C program is a set of declarations and function definitions; execution starts at main, and its return value becomes the process exit status.

Anatomy of a program
C

/* 3. Function prototype (declaration) */

/* 4. main: the entry point */

    counter++;
    printf("%s! square(7) = %d, counter = %d\n", GREETING, square(7), counter);

Declarations vs definitions

Declaration

Introduces a name and its type: int square(int x);, extern int count;. Can appear many times.

Definition

Declaration that also allocates storage or provides the body: int count = 0;, int square(int x) { … }. Exactly one per program (the one-definition rule).

Watch out

Calling a function before any declaration of it is an error since C99 (“implicit declaration”). Put prototypes at the top or in a header.

What happens before main runs?

The C runtime startup code (crt0/_start) sets up the stack, initialises .data and zeroes .bss, sets up stdin/stdout/stderr, builds argc/argv, then calls main. When main returns, exit() is called with its return value, which flushes buffers and runs atexit handlers.

What does the return value of main mean?

It is the process exit status passed to the operating system ($? in a shell). By convention 0 means success and non-zero means an error; only the low 8 bits are visible on POSIX systems.

Watch out

stdout is line-buffered on a terminal but fully buffered when redirected to a file or pipe. Output may appear later than you expect — use fflush(stdout) or print to stderr (unbuffered) for diagnostics.

Why is getchar's result stored in an int?

getchar returns every possible unsigned char value (0–255) plus EOF (a negative value, usually −1). A char cannot represent all 257 values, so EOF would be confused with a real character (or never detected if char is unsigned).

Why does printf use %f for both float and double, but scanf needs %lf for double?

Arguments to variadic functions undergo default argument promotions: a float passed to printf is converted to double, so %f always receives a double. scanf receives pointers, which are not promoted — it must know whether to write 4 bytes (float *, %f) or 8 bytes (double *, %lf).

What is the size of int in C?

Implementation-defined; the standard only requires at least 16 bits. On virtually every modern desktop/server platform (ILP32, LP64, LLP64) it is 32 bits. That is why portable code uses <stdint.h> types such as int32_t when the exact width matters.

Is char signed or unsigned?

Implementation-defined. char, signed char and unsigned char are three distinct types. Use unsigned char for raw bytes and cast to unsigned char before passing a char to <ctype.h> functions.

What does sizeof('A') return in C and in C++?

In C a character constant has type int, so sizeof('A') is sizeof(int) (usually 4). In C++ it has type char, so the result is 1.

When should you use int vs int32_t?

What is size_t and why is it unsigned?

size_t is the unsigned integer type returned by sizeof and taken by malloc, strlen, memcpy… It is large enough to hold the size of any object. It is unsigned because sizes are never negative — beware loops like for (size_t i = n - 1; i >= 0; i--), which never end.

Variables, Constants & Literals

A variable is a named, typed region of memory. C gives you three kinds of constants: literals, const objects, and #define / enum names.

Watch out

Identifier rules

  • Names starting with _ + uppercase letter or __ are reserved for the implementation — don’t use them.

What is the difference between #define and const?

#define is a preprocessor text replacement: no type, no scope, no storage, invisible to the debugger, and prone to precedence surprises. const creates a typed, scoped, read-only object with an address. What value does an uninitialised variable have?

Objects with static storage duration (globals, static locals) are zero-initialised. Automatic locals have an indeterminate value; reading it is undefined behaviour, which is why compilers warn (-Wuninitialized).

What are the differences between a static local variable and a global variable?

Both have static storage duration (they live for the whole program and are zero-initialised). A static local is only visible inside its function (block scope), whereas a global is visible to the whole file and — unless declared static — to other files via extern.

It gives the function internal linkage: it can only be called from the translation unit that defines it. This is C’s way of making a function private and avoids name clashes between files.

No, not in C. Objects with static storage duration must be initialised with constant expressions because the initial values are baked into the executable’s data segment before main runs. (C++ allows dynamic initialisation.)

What is the difference between i++ and ++i?

Both add 1 to i. The value of the expression differs: i++ yields the old value, ++i yields the new value. As a standalone statement (i++;) they are identical and compile to the same code.

What does short-circuit evaluation mean?

&& stops as soon as the left side is false, || stops as soon as the left side is true, and there is a sequence point after the left operand. That makes guards like if (p != NULL && p->count > 0) safe.

Before most arithmetic, C silently converts operands: small integers are promoted to int, and mixed types are brought to a common type. Signed/unsigned mixing is the classic source of bugs.

Why does (unsigned char)255 + 1 give 256 and not 0?

Because of integer promotion: the unsigned char operand is promoted to int before the addition, so the arithmetic is done in int. The result only wraps to 0 if it is stored back into an unsigned char.

What is the result of -1 < 0u?

0 (false). -1 is converted to unsigned int (becoming UINT_MAX) because both operands have the same rank and one is unsigned. This is why comparing an int with strlen() or sizeof can go wrong.

How do you check whether the k-th bit of n is set?

(n >> k) & 1 or n & (1u << k) (non-zero means set). Use unsigned operands so shifts into the top bit are well defined.

How do you find the element that appears once when all others appear twice?

XOR all elements: x ^ x == 0 and x ^ 0 == x, and XOR is commutative, so pairs cancel and only the single element remains. O(n) time, O(1) space.

Rules
  • The controlling expression must have an integer type (int, char, enum…) — not a string or double.
  • case labels must be integer constant expressions and unique. const int variables are not allowed in C; use enum or #define.
  • default is optional and may appear anywhere; it runs when no case matches.
  • Declaring a variable right after a case label needs a block: case 1: { int t = 0; … break; }.
  • For strings, use if/else if with strcmp.

For dense integer cases the compiler can turn a switch into a jump table (O(1) dispatch) or a binary search; an if-chain is tested top to bottom. Modern optimisers often transform both, so choose for readability: switch for many discrete values of one integer, if for ranges and complex conditions.

while checks the condition before each iteration, so the body may run zero times. do-while checks after, so the body always runs at least once — useful for menus and input validation loops.

An unsigned value is always >= 0; when i is 0, i-- wraps to UINT_MAX. Use a signed index or the for (size_t i = n; i-- > 0; ) idiom.

A function packages a computation behind a name and a prototype. C passes every argument by value — the function receives copies; to modify the caller’s variable you pass its address.

Declaration, definition, call
C
#include <stdio.h>

double average(const int *values, int count);   /* prototype */

int main(void) {
    int marks[] = {70, 85, 90};
    printf("%.2f\n", average(marks, 3));
    return 0;
}

double average(const int *values, int count) {  /* definition */
    if (count == 0) return 0.0;
    long sum = 0;
    for (int i = 0; i < count; i++) sum += values[i];
    return (double)sum / count;
}
Output
81.67

Call by value
C
#include <stdio.h>

void broken_swap(int a, int b) {    /* swaps the copies only */
    int t = a; a = b; b = t;
}

void swap(int *a, int *b) {         /* receives addresses ("call by reference" emulation) */
    int t = *a; *a = *b; *b = t;
}

int main(void) {
    int x = 1, y = 2;
    broken_swap(x, y);
    printf("after broken_swap: %d %d\n", x, y);
    swap(&x, &y);
    printf("after swap:        %d %d\n", x, y);
    return 0;
}
Output
after broken_swap: 1 2
after swap:        2 1
Key point

Even the pointer is passed by value: swap gets copies of the addresses. It can change what they point to, but not where the caller’s pointer variables point. To change a caller’s pointer, pass a pointer to it (int **).

Arrays and structs as parameters
  • An array argument decays to a pointer to its first element: void f(int a[]) is exactly void f(int *a). The size is lost — pass it separately.
  • A struct is copied in full. For big structs pass const struct T * to avoid the copy.
  • Mark pointer parameters you don’t modify as const — it documents intent and lets the compiler check it.
Returning several values
C
#include <stdio.h>

/* return a status, deliver results through out-parameters */
int divide(int a, int b, int *quot, int *rem) {
    if (b == 0) return -1;
    *quot = a / b;
    *rem = a % b;
    return 0;
}

int main(void) {
    int q, r;
    if (divide(17, 5, &q, &r) == 0)
        printf("17 = 5 * %d + %d\n", q, r);
    if (divide(1, 0, &q, &r) != 0)
        printf("division by zero rejected\n");
    return 0;
}

inline and the order of evaluation
  • static inline int sq(int x) { return x * x; } — a hint to expand the body at the call site; typical in headers as a type-safe macro replacement.
  • The order in which arguments are evaluated is unspecified: in f(g(), h()) either may run first. Never depend on it.
  • A function with a non-void return type that falls off the end without return — and whose value is used — is undefined behaviour (-Wreturn-type).

Does C support call by reference?

No — C only has call by value. Passing a pointer emulates call by reference: the pointer is copied, but both copies point to the same object, so the callee can modify it through *p.

What is a function prototype and why is it needed?

A declaration giving the return type and parameter types (int max(int, int);). It lets the compiler check calls, convert arguments to the right types and catch mistakes, even if the definition appears later or in another file.

What is the difference between f() and f(void) in a declaration?

Before C23, int f(); declares a function taking an unspecified number of arguments (old K&R style — no checking), while int f(void); declares a function that takes no arguments. C23 makes them equivalent, but (void) is still the portable choice.

Recursion

A recursive function calls itself on a smaller problem until it reaches a base case. Each call gets its own stack frame, so depth is limited by the stack size.

Anatomy
C
#include <stdio.h>

unsigned long long factorial(unsigned n) {
    if (n <= 1) return 1;              /* base case */
    return n * factorial(n - 1);       /* recursive case: smaller input */
}

int main(void) {
    for (unsigned i = 0; i <= 5; i++) printf("%u! = %llu\n", i, factorial(i));
    printf("20! = %llu\n", factorial(20));
    return 0;
}

Exponential blow-up and memoisation
C
#include <stdio.h>

static long calls = 0;

long fib_naive(int n) {
    calls++;
    return n < 2 ? n : fib_naive(n - 1) + fib_naive(n - 2);

long memo[91];
long fib_memo(int n) {
    if (n < 2) return n;
    if (memo[n]) return memo[n];

}

Watch out

Missing or unreachable base case → infinite recursion → stack overflow (segfault). Default stacks are only ~8 MB on Linux/macOS main threads, often much less on threads and embedded targets.

What is tail recursion?

A call is a tail call when it is the last action of the function (return f(n - 1, acc * n);). The compiler can then reuse the current stack frame, turning recursion into a loop. C compilers do this at higher optimisation levels, but the standard does not guarantee it.

What is the time complexity of naive recursive Fibonacci?

O(φⁿ) ≈ O(1.618ⁿ) calls because every call branches into two overlapping subproblems. Memoisation or a bottom-up loop makes it O(n).

Linkage — can other files see it?

External

Globals and functions by default. The same name in every file refers to one object.

Internal

static at file scope. Private to one translation unit.

None

Locals and parameters. Every declaration is a distinct object.

What is the difference between scope and lifetime?

Scope is a compile-time property of a name (the region of source where it can be used). Lifetime is a run-time property of an object (when its storage exists). A static local has block scope but lives for the whole program; a malloced object has no name at all but lives until free.

What is variable shadowing?

Declaring a variable in an inner scope with the same name as one in an outer scope; the inner name hides the outer one until its block ends. It is legal but confusing — -Wshadow warns about it.

Arrays & Strings

Arrays

An array is a fixed-size block of contiguous elements of one type, indexed from 0. C never checks the index — staying in bounds is your job.

Declaring and initialising
C
#include <stdio.h>

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    int b[5] = {1, 2};              /* rest are zero: 1 2 0 0 0 */
    int c[] = {7, 8, 9};            /* size deduced: 3 */
    int d[5] = {0};                 /* all zeros */
    int e[6] = {[2] = 5, [4] = 9};  /* designated initializers (C99) */

    size_t n = sizeof a / sizeof a[0];     /* element count */
    printf("n=%zu sizeof(c)=%zu\n", n, sizeof c);
    for (int i = 0; i < 5; i++) printf("%d ", b[i]);
    printf("| %d | ", d[3]);
    for (int i = 0; i < 6; i++) printf("%d ", e[i]);
    printf("\n");
    return 0;
}
Output
n=5 sizeof(c)=12
1 2 0 0 0 | 0 | 0 0 5 0 9 0
Key point

sizeof arr / sizeof arr[0] gives the element count — but only where arr is a real array. Inside a function that received it as a parameter, arr is a pointer and the trick silently returns 2 (8 / 4).

Passing arrays to functions
C
#include <stdio.h>

/* the array decays to a pointer: the size must travel separately */
int max_of(const int arr[], size_t n) {
    int best = arr[0];
    for (size_t i = 1; i < n; i++)
        if (arr[i] > best) best = arr[i];
    return best;
}

void double_all(int *arr, size_t n) {     /* same as int arr[] */
    for (size_t i = 0; i < n; i++) arr[i] *= 2;
}

int main(void) {
    int v[] = {3, 9, 2, 7};
    size_t n = sizeof v / sizeof v[0];
    double_all(v, n);                      /* modifies the caller's array */
    printf("max = %d, v[0] = %d\n", max_of(v, n), v[0]);
    return 0;
}

    return 0;
}

Why can't you assign one array to another with =?

An array is not a modifiable lvalue: in most expressions its name decays to a pointer to its first element, so a = b would mean assigning to an address. Copy element by element or with memcpy(a, b, sizeof a). (Wrapping an array in a struct makes it copyable by assignment.)

What is array decay?

In almost every expression, an array of T is converted to a pointer to its first element (T *). The exceptions are sizeof arr, &arr and a string literal used to initialise a char array. Decay is why functions cannot know an array's length.

Multi-dimensional Arrays

A 2-D array in C is an array of arrays, stored row by row (row-major) in one contiguous block.

C
#include <stdio.h>

int main(void) {
    int m[2][3] = {
        {1, 2, 3},
        {4, 5, 6},
    };
    for (int r = 0; r < 2; r++) {
        for (int c = 0; c < 3; c++) printf("%d ", m[r][c]);
        printf("\n");
    }
    printf("sizeof m = %zu, sizeof m[0] = %zu\n", sizeof m, sizeof m[0]);

    int *flat = &m[0][0];               /* row-major: rows are laid end to end */
    for (int i = 0; i < 6; i++) printf("%d ", flat[i]);
    printf("\n");
    return 0;
}

Performance

Iterate row by row (for r … for c …) — row-major order visits memory sequentially and is cache-friendly. Swapping the loops on a big matrix can be several times slower.

How is int a[3][4] laid out in memory?

As 12 consecutive ints: row 0 (4 ints), then row 1, then row 2. a[i] is an int[4] array, a decays to int (*)[4] (pointer to a row), and a[i][j] is *(*(a + i) + j).

Why must a function parameter for a 2-D array specify the column count?

To compute the address of m[r][c] the compiler needs the length of each row (r × COLS + c). The first dimension is not needed because the parameter is really a pointer to a row.

Strings in C

C has no string type. A string is an array of char terminated by a NUL byte '\0' — every string function walks the bytes until it finds that terminator.

Key point

Prefer strtol / strtod over atoi / atof: they report where parsing stopped and set errno to ERANGE on overflow. Use snprintf (never sprintf) to build strings safely.

Pitfalls
C — writing to a string literal (bus error / segfault at run time)
int main(void) {
    char *s = "hello";      /* legal in C (not C++), but the literal is read-only */
    s[0] = 'H';             /* undefined behaviour: crashes on most systems */
    return 0;
}
  • Forgetting room for '\0': char s[5] = "hello"; compiles in C but has no terminator.
  • Comparing with == compares addresses — use strcmp.
  • Returning a pointer to a local char array from a function (it dies on return).
  • Passing a plain char (possibly negative) to isalpha / toupper — cast to unsigned char first.
What is the difference between char s[] = "abc" and char *s = "abc"?

The first creates a 4-byte array on the stack (or in .data) initialised with a copy of the literal — you can modify it. The second creates a pointer to the literal itself, which lives in read-only memory; modifying it is undefined behaviour. sizeof gives 4 vs 8.

How is the length of a C string determined?

By scanning for the NUL terminator — strlen is O(n). The length is not stored anywhere, which is why repeated strlen calls in a loop condition (for (i = 0; i < strlen(s); i++)) make a loop O(n²).

strncpy(d, s, n) does not add '\0' when s has n or more characters, and it pads with zeros otherwise. Prefer snprintf(d, size, "%s", s) or set d[n - 1] = '\0' yourself.

What is the difference between memcpy and memmove?

Both copy n bytes. memcpy assumes the source and destination do not overlap (undefined behaviour if they do), so it can copy in any order and is slightly faster. memmove handles overlap correctly, as if copying through a temporary buffer.

Why is strtok considered unsafe?

It modifies the input string (writes \0 over delimiters), cannot be used on string literals, and keeps a hidden static pointer between calls — so it is not thread-safe and you cannot tokenise two strings at once. POSIX strtok_r takes the state as a parameter.

What is the size of a pointer?

It depends on the platform, not on the pointed-to type: 8 bytes on 64-bit systems, 4 on 32-bit. sizeof(char *) == sizeof(double *) on all mainstream platforms (function pointers can differ on exotic ones).

What is the difference between NULL, 0 and '\0'?

NULL is a null pointer constant (usually ((void *)0)). 0 is an integer that also acts as a null pointer constant in pointer context. '\0' is the NUL character (an int with value 0) used to terminate strings. They compare equal to zero but mean different things — use each in its own role. C23 adds nullptr.

Why use pointers at all?

To let functions modify caller data (out-parameters), to pass large objects cheaply, to work with dynamically allocated memory, to build linked data structures (lists, trees, graphs), to iterate arrays efficiently and to implement callbacks via function pointers.

If int *p = (int *)1000, what is p + 1?

1004 on a platform with 4-byte int — pointer arithmetic scales by the size of the pointed-to type. For char * it would be 1001, for double * 1008.

Can you subtract two pointers? Add them?

You can subtract two pointers into the same array: the result is the number of elements between them (ptrdiff_t). Adding two pointers is meaningless and a compile error.

Are arrays and pointers the same in C?

No. An array is a contiguous block of objects; a pointer is a single variable holding an address. They behave alike because an array expression decays to a pointer to its first element and a[i] is defined via pointer arithmetic. They differ in sizeof, in assignability and in what & produces.

What is the difference between const char *p, char const *p and char *const p?

The first two are identical: a (modifiable) pointer to read-only chars. The third is a read-only pointer to modifiable chars — p must be initialised and can never point elsewhere. Rule: const applies to what is on its left, or to the right if nothing is on the left.

How do you declare a function that returns a function pointer?

Directly: int (*get_op(char c))(int, int); — get_op takes a char and returns a pointer to a function (int, int) -> int. With a typedef it is readable: typedef int (*binop)(int, int); binop get_op(char c);.

What are function pointers used for in real systems?

Callbacks (qsort, bsearch, atexit, signal, event handlers), dispatch/jump tables for interpreters and state machines, plug-in interfaces (a struct of function pointers is C's version of a vtable — e.g. Linux struct file_operations), and dynamic loading with dlsym.

void Pointers & Generic Code

void * is a pointer to something of unknown type. Any object pointer converts to and from it implicitly — it is how C writes generic code (malloc, memcpy, qsort).

C
#include <stdio.h>

void print_value(const void *p, char type) {
    switch (type) {
        case 'i': printf("int %d\n", *(const int *)p); break;
        case 'd': printf("double %.2f\n", *(const double *)p); break;
        case 's': printf("string %s\n", (const char *)p); break;
    }
}

int main(void) {
    int i = 7;
    double d = 2.5;
    print_value(&i, 'i');
    print_value(&d, 'd');
    print_value("text", 's');
    return 0;
}

double 2.50
string text
Rules
  • You cannot dereference a void * — cast it to a concrete type first.
  • No pointer arithmetic on void * in standard C (GCC allows it as an extension, treating the size as 1).
  • T * → void * → T * round-trips safely. Converting to the wrong type and dereferencing is undefined behaviour.
  • In C, malloc’s void * result needs no cast: int *p = malloc(n * sizeof *p);. (C++ requires one.)
  • Function pointers are not guaranteed to convert to void * (POSIX allows it for dlsym).

Watch out

void * throws away type checking — the compiler can no longer catch a wrong cast. Keep the void * boundary thin and convert back to real types immediately.

Why can't a void pointer be dereferenced?

Dereferencing needs to know the size and interpretation of the object. void is an incomplete type with no size, so the compiler cannot generate a load or store — you must first cast to a complete type.

Why does qsort's comparator take const void *?

qsort is written once for every element type, so it only knows the base address, the element count and the element size. It hands the comparator pointers to two elements as const void *; the comparator, which knows the real type, casts them back.

typedef struct {
    int *data;
    size_t len, cap;

int vec_push(Vec *v, int x) {
    if (v->len == v->cap) {
        size_t new_cap = v->cap ? v->cap * 2 : 1;          /* geometric growth: amortised O(1) */
        int *tmp = realloc(v->data, new_cap * sizeof *tmp);
        if (!tmp) return -1;                              /* v->data is still valid */

        v->cap = new_cap;
        printf("grew to %zu\n", new_cap);

    return 0;
}

    for (int i = 1; i <= 5; i++) vec_push(&v, i * 10);

    return 0;
}

    char *copy = malloc(n);
    if (copy) memcpy(copy, s, n);
    return copy;

Person *person_new(const char *name, int age) {
    Person *p = malloc(sizeof *p);
    if (!p) return NULL;
    p->name = dup_string(name);
    if (!p->name) { free(p); return NULL; }
    p->age = age;
    return p;
}

void person_free(Person *p) {
    if (!p) return;
    free(p->name);                          /* inner allocations first */
    free(p);
}

int main(void) {
    Person *p = person_new("Ada", 36);
    if (!p) return 1;
    printf("%s is %d\n", p->name, p->age);
    person_free(p);
    return 0;
}

Rules of ownership
  • Every malloc/calloc/realloc success is matched by exactly one free of the same pointer.
  • Only pass free a pointer that came from an allocation function (not a stack array, not p + 1).
  • Decide and document who owns each allocation — the function that creates it, or the caller.
  • Free nested allocations before the struct that points to them.
  • Check sizes for overflow: n * size can wrap; calloc checks for you.
  • Leak checkers: Valgrind (valgrind --leak-check=full ./app), LeakSanitizer (-fsanitize=address on Linux).
What is the difference between malloc and calloc?

malloc(bytes) returns uninitialised memory. calloc(count, size) returns zero-filled memory for count elements and checks the multiplication for overflow. calloc can be as fast as malloc for large blocks because the OS hands out pre-zeroed pages.

What happens if you call free twice on the same pointer?

Undefined behaviour — a double free. It typically corrupts the allocator’s internal lists, can crash later in an unrelated malloc, and is exploitable. Setting the pointer to NULL after freeing makes a second free(NULL) harmless.

Does free return memory to the operating system?

Not necessarily. free returns the block to the allocator’s free lists so later mallocs can reuse it. Large blocks (served by mmap) are usually returned immediately; small ones typically stay with the process.

Should you cast the result of malloc in C?

No. void * converts implicitly to any object pointer type in C, and a cast can hide a missing #include <stdlib.h> in old compilers. The cast is required only in C++.

Stack frames

Each call pushes a frame: return address, saved registers, parameters that don’t fit in registers, and locals. Returning pops it — which is exactly why a pointer to a local is dangling after the return.

char big[16 * 1024 * 1024]; as a local, or unbounded recursion, overflows the stack. Put large buffers on the heap or make them static.

Where are string literals stored?

In a read-only data segment (.rodata), with static storage duration. Identical literals may share storage. Modifying one is undefined behaviour and usually crashes.

What is the difference between .data and .bss?

Both hold objects with static storage duration. .data holds those with a non-zero initialiser — their initial bytes are stored in the executable. .bss holds zero-initialised ones; the file records only the total size and the loader zero-fills it, keeping executables small.

Why does the stack grow down and the heap grow up?

Historically, so both could share one free region between them and each could grow until they met, without choosing a fixed split in advance. Modern systems use separate mappings with guard pages, but the convention remains on most architectures.

What is a dangling pointer and how do you avoid it?

A pointer that still holds the address of an object whose lifetime has ended — freed heap memory, or a local of a function that returned. Avoid it by setting pointers to NULL after free, never returning addresses of locals, and having a clear ownership rule for every allocation.

What is the difference between a memory leak and a dangling pointer?

A leak is memory that is still allocated but no longer reachable (no pointer to it) — wasted but harmless to correctness. A dangling pointer is the opposite: a pointer still exists but the memory is gone — using it is undefined behaviour.

How does AddressSanitizer work?

The compiler instruments every memory access with a check against shadow memory that records which bytes are addressable. The runtime surrounds allocations with poisoned redzones and quarantines freed blocks, so overflows and use-after-free hit poisoned bytes and are reported immediately with stack traces. Cost: ~2× slowdown and more memory.

  • Compile with -Wall -Wextra and fix every warning.
  • Test with -fsanitize=undefined,address (and thread for concurrency).

  • Validate inputs before arithmetic, indexing and shifting.

What is undefined behaviour and why does C have it?

Behaviour for which the standard imposes no requirements. It exists so C can map directly onto very different hardware and so compilers can optimise aggressively without inserting checks (bounds, overflow, null) — the programmer promises these situations never occur.

Why can undefined behaviour 'time travel'?

Because a program that executes UB has no defined meaning at all, the optimiser may assume the UB path is never taken and reason backwards — e.g. dereferencing p before a if (p == NULL) check lets the compiler delete the check, since p “must” be non-null.

Is i = i++ undefined?

Yes (in C). i is modified twice without an intervening sequence point — once by the assignment and once by the post-increment. C11 describes this as two unsequenced side effects on the same object, which is undefined.

What is the difference between . and -> ?

. accesses a member of a struct object; -> accesses a member through a pointer to a struct. p->m is shorthand for (*p).m.

Can you compare two structs with ==?

No — C does not define == for structs. Compare members individually. memcmp is unreliable because padding bytes have unspecified values (and floating-point -0.0/NaN compare differently from their bytes).

Why can't a struct contain a member of its own type?

It would have infinite size. It can contain a pointer to its own type, because a pointer has a fixed size — that is how linked lists and trees are built.

What is structure padding and why does it exist?

Unused bytes the compiler inserts between (and after) struct members so that each member sits at an address that is a multiple of its alignment. Aligned loads/stores are a single fast instruction; misaligned ones are slower or fault on some architectures.

What is sizeof(struct { char c; double d; })?

16 on typical 64-bit platforms: c at offset 0, 7 bytes of padding, d at offset 8 (aligned to 8), total 16. Reversing the members gives 9 bytes of data rounded up to 16 as well (tail padding).

How do you find the offset of a member?

offsetof(type, member) from <stddef.h>. It is used for serialisation, for generic containers and in the Linux kernel’s container_of macro to get from a member pointer back to the enclosing struct.

What is the difference between a structure and a union?

In a struct every member has its own storage, so all can hold values simultaneously and the size is at least the sum of the members. In a union all members start at the same address and share storage, so the size is that of the largest member and writing one member overwrites the others.

How can you check the endianness of a machine?

Store a multi-byte integer such as 1 and inspect its first byte through a unsigned char * or a union: if the first byte is 1 the machine is little-endian (x86, ARM in its usual mode), otherwise big-endian.

C enums are weakly typed: an enum variable is just an integer, and any int can be assigned to it without a diagnostic. Enumerator names share one namespace — prefix them (COLOR_RED) to avoid clashes.

What is the default value of the first enumerator, and of the ones after it?

Implementation-defined: an integer type able to represent all enumerators — int (4 bytes) on common compilers. C23 lets you fix it: enum Small : unsigned char { A, B };.

Bit-fields

A bit-field is a struct member with an explicit width in bits. It packs several small values into one integer — flags, compact records, protocol headers.

C — compiled with -Wno-bitfield-constant-conversion to show the truncation
#include <stdio.h>

struct Flags {
    unsigned int visible  : 1;
    unsigned int editable : 1;
    unsigned int priority : 3;     /* 0..7 */
    unsigned int reserved : 3;
};

struct Date {                      /* day 1-31, month 1-12, year offset 0-127 */
    unsigned int day   : 5;
    unsigned int month : 4;
    unsigned int year  : 7;
};

int main(void) {
    struct Flags f = {.visible = 1, .priority = 5};
    f.editable = 1;
    printf("%u %u %u, sizeof = %zu\n", f.visible, f.editable, f.priority, sizeof f);

    f.priority = 9;                /* 9 doesn't fit in 3 bits: stored modulo 8 */
    printf("priority now %u\n", f.priority);

    struct Date d = {29, 9, 26};   /* 2026 as an offset from 2000 */
    printf("%02u/%02u/%u in %zu bytes\n", d.day, d.month, 2000 + d.year, sizeof d);
    return 0;
}
Output

priority now 1
29/09/2026 in 4 bytes
Rules and limits
  • Allowed types: unsigned int, signed int, _Bool (and others as an extension). Use unsigned — the signedness of a plain int bit-field is implementation-defined.
  • You cannot take the address of a bit-field (&f.visible is an error) or make arrays of them.
  • Layout (bit order, whether fields straddle storage units, padding) is implementation-defined — don’t use bit-fields to match an external binary format portably.
  • An unnamed field unsigned : 0; forces the next field to start in a new storage unit.
  • Reading/writing a bit-field compiles to load-mask-shift-store — slower than a plain int, and not atomic.

Can you take the address of a bit-field member?

No. Bit-fields may start in the middle of a byte, and pointers address whole bytes, so &s.field is a compile error. sizeof can't be applied to a bit-field either.

What is the size of struct { unsigned a:3; unsigned b:5; }?

Typically 4 bytes: both fields fit into one unsigned int storage unit (8 bits used), and the struct is padded to the alignment of unsigned int. The exact layout is implementation-defined.

The standard library uses it: void *memcpy(void *restrict dst, const void *restrict src, size_t n); — which is precisely why overlapping memcpy is undefined and memmove (no restrict) exists.

Can a variable be both const and volatile?

Yes — e.g. const volatile uint32_t *status_reg: the program must not write it (const) but hardware can change it at any time, so every read must go to memory (volatile). A read-only hardware status register is the classic example.

What happens if you break a restrict promise?

Undefined behaviour. The compiler optimised assuming no aliasing (e.g. keeping values in registers or reordering loads), so overlapping pointers can produce wrong results silently.

Singly Linked List

A chain of heap-allocated nodes, each pointing to the next. O(1) insertion at the head, O(n) search — and the most common C interview data structure.

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int data;
    struct Node *next;
} Node;

Node *new_node(int v) {
    Node *n = malloc(sizeof *n);
    if (!n) { perror("malloc"); exit(EXIT_FAILURE); }
    n->data = v;
    n->next = NULL;
    return n;
}

void push_front(Node **head, int v) {        /* O(1) */
    Node *n = new_node(v);
    n->next = *head;
    *head = n;
}

void push_back(Node **head, int v) {         /* O(n): walk to the tail */
    Node **pp = head;
    while (*pp) pp = &(*pp)->next;
    *pp = new_node(v);
}

int remove_value(Node **head, int v) {       /* pointer-to-pointer: no special case for head */
    for (Node **pp = head; *pp; pp = &(*pp)->next) {
        if ((*pp)->data == v) {
            Node *dead = *pp;
            *pp = dead->next;
            free(dead);
            return 1;
        }
    }
    return 0;
}

void reverse(Node **head) {                  /* O(n), O(1) space */
    Node *prev = NULL, *cur = *head;
    while (cur) {
        Node *next = cur->next;
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    *head = prev;
}

void print(const Node *n) {
    for (; n; n = n->next) printf("%d -> ", n->data);
    printf("NULL\n");
}

void free_list(Node *n) {
    while (n) { Node *next = n->next; free(n); n = next; }
}

int main(void) {
    Node *head = NULL;
    push_back(&head, 2);
    push_back(&head, 3);
    push_front(&head, 1);
    push_back(&head, 4);
    print(head);
    remove_value(&head, 1);
    remove_value(&head, 3);
    print(head);
    reverse(&head);
    print(head);
    free_list(head);
    return 0;
}

        if (a->data <= b->data) { t->next = a; a = a->next; }
        else                    { t->next = b; b = b->next; }
        t = t->next;
    }
    t->next = a ? a : b;
    return dummy.next;
}

How do you reverse a singly linked list?

Iteratively with three pointers: prev = NULL, cur = head; for each node save next, point cur->next to prev, then advance prev = cur, cur = next. At the end prev is the new head. O(n) time, O(1) space.

How do you detect a cycle in a linked list?

Floyd’s algorithm: move a slow pointer one step and a fast pointer two steps; if they ever meet there is a cycle, if the fast pointer reaches NULL there isn’t. To find the cycle start, reset one pointer to the head and move both one step at a time — they meet at the entry.

Doubly & Circular Linked Lists

A doubly linked list stores prev and next pointers, so a node can be removed in O(1) given only a pointer to it and the list can be walked both ways.

C
#include <stdio.h>
#include <stdlib.h>

typedef struct DNode {
    int data;
    struct DNode *prev, *next;
} DNode;

/* circular list with a sentinel: no NULL checks at the ends */
typedef struct { DNode head; size_t size; } List;

void list_init(List *l) { l->head.prev = l->head.next = &l->head; l->size = 0; }

void insert_after(List *l, DNode *pos, int v) {
    DNode *n = malloc(sizeof *n);
    if (!n) exit(1);
    n->data = v;
    n->prev = pos;
    n->next = pos->next;
    pos->next->prev = n;
    pos->next = n;
    l->size++;
}

void push_front(List *l, int v) { insert_after(l, &l->head, v); }
void push_back(List *l, int v)  { insert_after(l, l->head.prev, v); }

void unlink_node(List *l, DNode *n) {        /* O(1): no search for the predecessor */
    n->prev->next = n->next;
    n->next->prev = n->prev;
    free(n);
    l->size--;
}

void print(const List *l) {
    for (const DNode *n = l->head.next; n != &l->head; n = n->next) printf("%d ", n->data);
    printf("| backwards: ");
    for (const DNode *n = l->head.prev; n != &l->head; n = n->prev) printf("%d ", n->data);
    printf("(size %zu)\n", l->size);
}

int main(void) {
    List l;
    list_init(&l);
    push_back(&l, 2); push_back(&l, 3); push_front(&l, 1); push_back(&l, 4);
    print(&l);
    unlink_node(&l, l.head.next->next);       /* remove the 2 */
    print(&l);
    while (l.size) unlink_node(&l, l.head.next);
    print(&l);
    return 0;
}

Why is deletion O(1) in a doubly linked list but O(n) in a singly linked one?

To unlink a node you must update its predecessor’s next. A doubly linked node knows its predecessor (prev); in a singly linked list you have to walk from the head to find it (unless you already hold it).

#include <stdio.h>
#include <stdbool.h>

#define QCAP 4

typedef struct { int buf[QCAP]; int head, count; } Queue;

bool enqueue(Queue *q, int v) {
    if (q->count == QCAP) return false;               /* full */
    q->buf[(q->head + q->count) % QCAP] = v;          /* wrap around */
    q->count++;
    return true;
}

bool dequeue(Queue *q, int *out) {
    if (q->count == 0) return false;                  /* empty */
    *out = q->buf[q->head];
    q->head = (q->head + 1) % QCAP;
    q->count--;
    return true;
}

    for (int i = 1; i <= 5; i++)

    int v;
    dequeue(&q, &v); printf("got %d\n", v);
    dequeue(&q, &v); printf("got %d\n", v);
    enqueue(&q, 60); enqueue(&q, 70);                  /* reuses freed slots */
    while (dequeue(&q, &v)) printf("%d ", v);
    printf("\n");
    return 0;
}

How do you implement a queue using two stacks?

Push onto an in stack. To dequeue, if the out stack is empty, pop everything from in and push it onto out (reversing the order), then pop from out. Each element moves at most twice, so operations are amortised O(1).

How do you tell a full circular buffer from an empty one?

head == tail is ambiguous, so either keep a separate count (as above), or always leave one slot unused ((tail + 1) % CAP == head means full).

Binary Search Tree

A binary tree where every left descendant is smaller and every right descendant is larger than the node. Search, insert and delete are O(h) — O(log n) when balanced, O(n) when degenerate.

C
#include <stdio.h>
#include <stdlib.h>

typedef struct Tree { int key; struct Tree *left, *right; } Tree;

Tree *insert(Tree *t, int key) {
    if (!t) {
        t = malloc(sizeof *t);
        if (!t) exit(1);
        t->key = key; t->left = t->right = NULL;
    } else if (key < t->key) t->left = insert(t->left, key);
    else if (key > t->key)   t->right = insert(t->right, key);
    return t;                                  /* duplicates ignored */
}

const Tree *search(const Tree *t, int key) {
    while (t && t->key != key) t = key < t->key ? t->left : t->right;
    return t;
}

Tree *delete(Tree *t, int key) {
    if (!t) return NULL;
    if (key < t->key) t->left = delete(t->left, key);
    else if (key > t->key) t->right = delete(t->right, key);
    else if (!t->left || !t->right) {          /* 0 or 1 child */
        Tree *child = t->left ? t->left : t->right;
        free(t);
        return child;
    } else {                                   /* 2 children: copy in-order successor */
        Tree *s = t->right;
        while (s->left) s = s->left;
        t->key = s->key;
        t->right = delete(t->right, s->key);
    }
    return t;
}

void inorder(const Tree *t)  { if (t) { inorder(t->left); printf("%d ", t->key); inorder(t->right); } }
void preorder(const Tree *t) { if (t) { printf("%d ", t->key); preorder(t->left); preorder(t->right); } }
int height(const Tree *t) {
    if (!t) return 0;
    int l = height(t->left), r = height(t->right);
    return 1 + (l > r ? l : r);
}
void destroy(Tree *t) { if (t) { destroy(t->left); destroy(t->right); free(t); } }  /* postorder */

int main(void) {
    Tree *root = NULL;
    int keys[] = {50, 30, 70, 20, 40, 60, 80};
    for (int i = 0; i < 7; i++) root = insert(root, keys[i]);

    printf("inorder:  "); inorder(root);  printf("\n");
    printf("preorder: "); preorder(root); printf("\n");
    printf("height %d, has 60? %s, has 65? %s\n", height(root),
           search(root, 60) ? "yes" : "no", search(root, 65) ? "yes" : "no");

    root = delete(root, 50);                   /* root with two children */
    printf("after deleting 50: "); inorder(root); printf("(root %d)\n", root->key);
    destroy(root);
    return 0;
}

How do you check whether a binary tree is a valid BST?

Recurse with an allowed range: every node’s key must lie strictly between a lower and upper bound inherited from its ancestors (check(node->left, lo, node->key), check(node->right, node->key, hi)). Comparing a node only with its direct children is not enough.

Hash Table

An array of buckets indexed by hash(key) % capacity. With a good hash function and a reasonable load factor, lookup, insert and delete are O(1) on average.

C
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define NBUCKETS 8

typedef struct Entry {
    char *key;
    int value;
    struct Entry *next;               /* separate chaining */
} Entry;

typedef struct { Entry *buckets[NBUCKETS]; size_t count; } Map;

unsigned long hash(const char *s) {   /* djb2 by Dan Bernstein */
    unsigned long h = 5381;
    for (; *s; s++) h = h * 33 + (unsigned char)*s;
    return h;
}

void map_put(Map *m, const char *key, int value) {
    size_t i = hash(key) % NBUCKETS;
    for (Entry *e = m->buckets[i]; e; e = e->next)
        if (strcmp(e->key, key) == 0) { e->value = value; return; }   /* update */
    Entry *e = malloc(sizeof *e);
    if (!e) exit(1);
    size_t n = strlen(key) + 1;
    e->key = malloc(n);
    if (!e->key) exit(1);
    memcpy(e->key, key, n);
    e->value = value;
    e->next = m->buckets[i];          /* insert at bucket head */
    m->buckets[i] = e;
    m->count++;
}

int *map_get(Map *m, const char *key) {
    for (Entry *e = m->buckets[hash(key) % NBUCKETS]; e; e = e->next)
        if (strcmp(e->key, key) == 0) return &e->value;
    return NULL;
}

void map_free(Map *m) {
    for (int i = 0; i < NBUCKETS; i++)
        for (Entry *e = m->buckets[i], *next; e; e = next) {
            next = e->next;
            free(e->key);
            free(e);
        }
}

int main(void) {
    Map m = {0};
    const char *words[] = {"the", "cat", "sat", "on", "the", "mat", "the", "cat"};
    for (int i = 0; i < 8; i++) {
        int *c = map_get(&m, words[i]);
        if (c) (*c)++; else map_put(&m, words[i], 1);
    }
    const char *probe[] = {"the", "cat", "mat", "dog"};
    for (int i = 0; i < 4; i++) {
        int *c = map_get(&m, probe[i]);
        printf("%s: %d\n", probe[i], c ? *c : 0);
    }
    printf("distinct words: %zu\n", m.count);
    map_free(&m);
    return 0;
}

What makes a good hash function?

It is fast, deterministic, and spreads typical keys uniformly across buckets so that small changes in the key change many output bits. For strings, FNV-1a, djb2 or xxHash/SipHash (the latter resists hash-flooding attacks) are common choices.

#include <stdbool.h>

void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

void bubble_sort(int *a, int n) {
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) { swap(&a[j], &a[j + 1]); swapped = true; }
        if (!swapped) break;                 /* already sorted: O(n) best case */
    }
}

void selection_sort(int *a, int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++) if (a[j] < a[min]) min = j;
        swap(&a[i], &a[min]);
    }
}

void insertion_sort(int *a, int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
}

void print(const int *a, int n) { for (int i = 0; i < n; i++) printf("%d ", a[i]); printf("\n"); }

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void merge(int *a, int *tmp, int lo, int mid, int hi) {
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];   /* <= keeps it stable */
    while (i < mid) tmp[k++] = a[i++];
    while (j < hi)  tmp[k++] = a[j++];
    memcpy(a + lo, tmp + lo, (size_t)(hi - lo) * sizeof *a);
}

static void msort(int *a, int *tmp, int lo, int hi) {     /* sorts a[lo, hi) */
    if (hi - lo < 2) return;
    int mid = lo + (hi - lo) / 2;
    msort(a, tmp, lo, mid);
    msort(a, tmp, mid, hi);
    merge(a, tmp, lo, mid, hi);
}

void merge_sort(int *a, int n) {
    int *tmp = malloc((size_t)n * sizeof *tmp);
    if (!tmp) return;
    msort(a, tmp, 0, n);
    free(tmp);
}

void quick_sort(int *a, int lo, int hi) {                 /* Lomuto partition, a[lo..hi] */
    if (lo >= hi) return;
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) { int t = a[i]; a[i] = a[j]; a[j] = t; i++; }
    int t = a[i]; a[i] = a[hi]; a[hi] = t;                /* pivot to its final place */
    quick_sort(a, lo, i - 1);
    quick_sort(a, i + 1, hi);
}

C
#include <stdio.h>

int binary_search(const int *a, int n, int key) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;     /* not (lo + hi) / 2: that can overflow */
        if (a[mid] == key) return mid;
        if (a[mid] < key) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

int lower_bound(const int *a, int n, int key) {   /* first index with a[i] >= key */
    int lo = 0, hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < key) lo = mid + 1; else hi = mid;
    }
    return lo;
}

int main(void) {
    int a[] = {2, 5, 8, 8, 8, 13, 21};
    printf("%d %d\n", binary_search(a, 7, 13), binary_search(a, 7, 4));
    printf("first 8 at %d, insert 9 at %d\n", lower_bound(a, 7, 8), lower_bound(a, 7, 9));
    return 0;
}

Key point

In production C, use qsort (see Function Pointers) and bsearch from <stdlib.h>. Write your own when you need stability (merge sort), a specialised key, or an interview asks for it.

Why is quicksort usually faster than merge sort in practice even though its worst case is O(n²)?

It sorts in place with a tight inner loop and excellent cache locality, and choosing the pivot randomly or by median-of-three makes the O(n²) case vanishingly unlikely. Merge sort needs O(n) extra memory and more data movement. Library sorts (introsort) switch to heap sort if recursion gets too deep, guaranteeing O(n log n).

What does it mean for a sort to be stable?

Elements with equal keys keep their original relative order. It matters when sorting records by one field after another (e.g. by name, then stably by department). Merge, insertion and bubble sort are stable; quick, heap and selection sort are not. qsort is not guaranteed stable.

What is the difference between text and binary mode?

On POSIX there is none. On Windows, text mode translates \n to \r\n on write (and back on read) and may treat Ctrl-Z as end-of-file; binary mode passes bytes through unchanged. Always use "rb"/"wb" for non-text data.

Why must you call fclose?

It flushes buffered data to the file (without it, the last writes may be lost if the program crashes or calls _exit), releases the file descriptor (processes have a limited number) and frees the FILE structure. exit and returning from main close open streams, but relying on that hides bugs.

What is the difference between a macro and an inline function?

A macro is textual substitution before compilation: no type checking, arguments may be evaluated several times, no scope, hard to debug. An inline function is a real function the compiler may expand in place: arguments are evaluated once and type-checked, and it follows normal scope rules. Macros are still needed for stringising, token pasting, conditional compilation and type-generic tricks.

Why wrap a multi-statement macro in do { ... } while (0)?

It turns the macro into a single statement that requires a trailing semicolon, so it works correctly as the body of an unbraced if/else. A bare { … } block followed by ; would break an if … else.

What does #include <file> vs #include "file" do?

Both paste the file’s contents. "file" searches the directory of the current file first, then the system paths; <file> searches only the system/-I paths. Use quotes for your own headers.

What is an include guard and why is it needed?

#ifndef X_H / #define X_H / … / #endif around a header’s content. Why separate declarations and definitions into .h and .c files?

It gives each module a public interface and a private implementation, allows separate compilation (only changed files are recompiled), lets many files share one set of declarations so the compiler checks every call, and keeps exactly one definition of each symbol for the linker.

Variadic Functions

Functions like printf take a variable number of arguments. <stdarg.h> lets you write your own: va_start, va_arg, va_end walk the extra arguments — with no type safety at all.

C
#include <stdio.h>
#include <stdarg.h>

/* the count is passed explicitly: the callee can't know how many arguments there are */
int sum(int count, ...) {
    va_list ap;
    va_start(ap, count);                 /* start after the last named parameter */
    int total = 0;
    for (int i = 0; i < count; i++)
        total += va_arg(ap, int);        /* you must know each argument's type */
    va_end(ap);
    return total;
}

/* a sentinel (negative number) marks the end instead */
double average(double first, ...) {
    va_list ap;
    va_start(ap, first);
    double s = 0;
    int n = 0;
    for (double x = first; x >= 0; x = va_arg(ap, double)) { s += x; n++; }
    va_end(ap);
    return n ? s / n : 0;
}

int main(void) {
    printf("%d %d\n", sum(3, 10, 20, 30), sum(0));
    printf("%.2f\n", average(1.0, 2.0, 4.5, -1.0));
    return 0;
}

    va_list ap;
    va_start(ap, fmt);
    printf("[%s] ", level);
    vprintf(fmt, ap);                    /* the v- variants take a va_list */
    printf("\n");
    va_end(ap);
}

Rules
  • At least one named parameter is required before ... (until C23).
  • Default argument promotions apply to the variadic part: char/short arrive as int, float as double. So va_arg(ap, float) or va_arg(ap, char) is wrong.
  • The callee must learn the number and types of the arguments some other way: a count, a sentinel, or a format string.
  • Reading more arguments than were passed, or with the wrong type, is undefined behaviour.
  • Every va_start (and va_copy) needs a matching va_end.
How does printf know how many arguments it received?

It doesn’t — it trusts the format string. Each conversion specifier tells it to fetch one more argument of a given type with va_arg. Too few arguments, or mismatched types, are undefined behaviour, which is why compilers check printf formats (-Wformat) and why user-controlled format strings are a security hole.

Why can't you use va_arg(ap, float)?

Because a float passed through ... is promoted to double by the caller. The callee must read it as double; asking for a float reads the wrong number of bytes / wrong register — undefined behaviour.

    if (!s || !*s) return ERR_EMPTY;

    for (; *s; s++) {

        v = v * 10 + (*s - '0');

    return ERR_OK;

        if (e == ERR_OK) printf("'%s' -> %d%%\n", inputs[i], p);

How do you handle errors in C without exceptions?

Return a status code (or NULL/-1) from every fallible function and pass results through out-parameters; check every return value; propagate errors upward; use errno / strerror for library failures; and structure cleanup with the goto cleanup pattern so each resource is released exactly once on every path. setjmp/longjmp exist for non-local jumps but skip cleanup and are rarely appropriate.

Is errno thread-safe?

Yes on modern systems: since C11, errno is a macro that expands to a thread-local lvalue (often (*__errno_location())), so each thread has its own copy.

What is the difference between time() and clock()?

time() returns wall-clock calendar time (seconds since the Unix epoch). clock() returns the processor time used by the program, in CLOCKS_PER_SEC units — it does not advance while the process sleeps. For precise wall-clock intervals use POSIX clock_gettime(CLOCK_MONOTONIC, …) or C11 timespec_get.

Threads & Atomics (Intro)

C11 standardised a memory model, <stdatomic.h> and an optional <threads.h>. In practice most C code uses POSIX threads (pthread). Shared data needs a mutex or atomics — otherwise it is a data race (undefined behaviour).

Creating and joining threads

#include <stdio.h>
#include <pthread.h>

typedef struct { int id; long from, to, result; } Job;

void *sum_range(void *arg) {                 /* thread entry: void *(*)(void *) */
    Job *job = arg;
    long s = 0;
    for (long i = job->from; i < job->to; i++) s += i;
    job->result = s;                          /* each thread writes only its own Job */
    return NULL;
}

int main(void) {
    enum { N = 4 };
    pthread_t tid[N];
    Job jobs[N];
    for (int i = 0; i < N; i++) {
        jobs[i] = (Job){i, i * 250000L, (i + 1) * 250000L, 0};
        pthread_create(&tid[i], NULL, sum_range, &jobs[i]);
    }
    long total = 0;
    for (int i = 0; i < N; i++) {
        pthread_join(tid[i], NULL);           /* wait, then read the result */
        total += jobs[i].result;
    }
    printf("sum 0..999999 = %ld\n", total);
    return 0;
}

Protecting shared state
C
#include <stdio.h>
#include <pthread.h>
#include <stdatomic.h>

long plain_counter = 0;
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
atomic_long atomic_counter = 0;

void *work(void *arg) {
    (void)arg;
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&lock);
        plain_counter++;                         /* critical section */
        pthread_mutex_unlock(&lock);
        atomic_fetch_add(&atomic_counter, 1);    /* lock-free alternative */
    }
    return NULL;
}

int main(void) {
    pthread_t t[4];
    for (int i = 0; i < 4; i++) pthread_create(&t[i], NULL, work, NULL);
    for (int i = 0; i < 4; i++) pthread_join(t[i], NULL);
    printf("mutex: %ld, atomic: %ld\n", plain_counter, atomic_load(&atomic_counter));
    return 0;
}

What is a race condition, and what is a deadlock?

A race condition is when the result depends on the unpredictable interleaving of threads — e.g. two threads doing count++ on shared data without synchronisation (in C a data race is undefined behaviour). A deadlock is when threads wait on each other forever — e.g. thread A holds lock 1 and wants lock 2 while thread B holds lock 2 and wants lock 1. Prevent deadlocks by always acquiring locks in a consistent global order.

Is volatile enough for sharing a flag between threads?

No. volatile prevents the compiler from caching the value but gives no atomicity and no ordering guarantees between CPU cores. Use _Atomic (e.g. atomic_bool) or a mutex.

What is _Generic used for?

Selecting an expression at compile time based on the type of a controlling expression — the foundation of type-generic macros like <tgmath.h>’s sqrt that call sqrtf, sqrt or sqrtl depending on the argument type. It gives C a limited form of overloading.

C99 syntax to initialise specific members or indexes by name: struct Point p = {.y = 2, .x = 1};, int a[10] = {[9] = 1};. Unmentioned members are zero-initialised, the order doesn’t matter, and the code survives reordering of struct fields.

Coding habits

Initialise everything

typedef struct {
    char  *data;
    size_t len;
} Text;

/* returns 0 on success; on failure *out is untouched and nothing leaks */
int text_read_file(const char *path, Text *out) {
    int rc = -1;
    char *buf = NULL;
    FILE *f = fopen(path, "rb");
    if (!f) goto done;
    if (fseek(f, 0, SEEK_END) != 0) goto done;
    long size = ftell(f);
    if (size < 0) goto done;
    rewind(f);
    buf = malloc((size_t)size + 1);
    if (!buf) goto done;
    if (fread(buf, 1, (size_t)size, f) != (size_t)size) goto done;
    buf[size] = '\0';
    out->data = buf;
    out->len = (size_t)size;
    buf = NULL;                  /* ownership transferred to *out */
    rc = 0;
done:
    free(buf);                   /* free(NULL) is fine */
    if (f) fclose(f);
    return rc;
}

int main(void) {
    FILE *f = fopen("note.txt", "w");
    if (!f) return 1;
    fputs("clean C", f);
    fclose(f);

    Text t = {0};
    if (text_read_file("note.txt", &t) == 0) {
        printf("%zu bytes: %s\n", t.len, t.data);
        free(t.data);
    }
    printf("missing file -> %d\n", text_read_file("missing.txt", &t));
    return 0;

Language fundamentals
What are the storage classes in C?

auto (default for locals: block scope, automatic lifetime), register (auto + no address; historic hint), static (static lifetime; internal linkage at file scope; value persists between calls as a local), extern (declares an object/function defined elsewhere, external linkage), and C11 _Thread_local. typedef is grammatically a storage-class specifier too.

What is the difference between declaration and definition?

A declaration tells the compiler a name and its type (extern int x;, int f(void);). A definition also creates the object or supplies the function body (int x = 0;, int f(void) { … }). A name can be declared many times but defined exactly once.

What is a volatile variable? Give examples.

A variable whose value can change outside the program’s visible control flow, so the compiler must perform every read and write exactly as written: memory-mapped hardware registers, variables modified in signal handlers (volatile sig_atomic_t), and memory changed by DMA. It does not provide thread synchronisation.

Explain const int *p, int *const p and const int *const p.

Pointer to const int (can’t modify *p, can move p); const pointer to int (can modify *p, can’t move p); const pointer to const int (neither). Read the declaration right to left.

What is the difference between ++i and i++ in a for loop?

None for int in a standalone increment — compilers generate identical code. The difference only matters when the expression’s value is used: i++ yields the old value, ++i the new one.

What are sequence points and why do they matter?

Points in execution where all previous side effects are complete: the end of a full expression (;), after the first operand of &&, ||, ?: and ,, and before a function call. Modifying an object twice (or modifying and reading it for another purpose) without an intervening sequence point is undefined behaviour — e.g. i = i++, a[i] = i++.

Pointers and memory
What is the difference between malloc and calloc? What does realloc do?

malloc(n) returns n uninitialised bytes; calloc(count, size) returns zeroed memory for count × size bytes with overflow checking. realloc(p, n) resizes a block, possibly moving it (copying the old contents); on failure it returns NULL and leaves the old block intact.

What are dangling pointers, wild pointers and memory leaks?

A dangling pointer points to memory that has been freed or gone out of scope. A wild pointer was never initialised and holds a garbage address. A leak is allocated memory that is no longer referenced by any pointer, so it can never be freed.

What is a NULL pointer vs a void pointer?

A null pointer is a value — a pointer of any type that points to nothing. A void * is a type — a generic pointer that can hold the address of any object but must be cast before dereferencing. A void * can itself be null.

Can you return a pointer to a local variable?

No — the local’s lifetime ends when the function returns, so the pointer dangles. Return by value, use a static local (not reentrant), write into a caller-provided buffer, or return heap memory that the caller frees.

What is the difference between arrays and pointers?

An array is a block of storage whose name decays to a pointer to its first element in most expressions; a pointer is a variable storing an address. sizeof differs (whole array vs pointer size), an array name can’t be assigned, and &array has type pointer-to-array.

How do you find the size of an array passed to a function?

You can’t — it has decayed to a pointer. Pass the length as a separate parameter (or use a sentinel such as '\0' for strings, or wrap the array in a struct).

What is memory alignment and structure padding?

Each type must be stored at an address that is a multiple of its alignment; the compiler inserts padding bytes between struct members and at the end to satisfy that for every member and for arrays of the struct. Ordering members from largest to smallest minimises padding.

Explain stack vs heap.

The stack holds function frames (locals, return addresses); allocation is automatic and very fast but the size is limited and data dies when the function returns. The heap holds malloc’d memory; it is large and lives until free, but allocation is slower and the programmer manages the lifetime (leaks, use-after-free).

    size_t n = strlen(s);
    if (n == 0) return;
    rev(s, s + n - 1);                               /* reverse whole string */
    for (char *w = s; *w; ) {                        /* then each word */
        while (*w == ' ') w++;
        char *e = w;
        while (*e && *e != ' ') e++;
        if (e > w) rev(w, e - 1);
        w = e;
    }
}

/* 2. endianness check */
int is_little_endian(void) { unsigned x = 1; return *(unsigned char *)&x == 1; }

/* 3. my_atoi with sign and overflow saturation */
int my_atoi(const char *s) {
    long v = 0;
    int sign = 1;
    while (*s == ' ') s++;
    if (*s == '-' || *s == '+') sign = (*s++ == '-') ? -1 : 1;
    while (*s >= '0' && *s <= '9') {
        v = v * 10 + (*s++ - '0');
        if (v > 2147483648L) break;
    }
    v *= sign;
    if (v > 2147483647L) return 2147483647;
    if (v < -2147483648L) return (int)-2147483648L;
    return (int)v;
}

/* 4. count set bits, reverse bits of a byte */
unsigned char reverse_byte(unsigned char b) {
    unsigned char r = 0;
    for (int i = 0; i < 8; i++) { r = (unsigned char)((r << 1) | (b & 1)); b >>= 1; }
    return r;
}

Tricky questions
What does printf return?

The number of characters written (excluding the terminating NUL), or a negative value on error. So printf("%d", printf("hello")) prints hello5.

What is the output of sizeof on an expression with side effects, e.g. sizeof(i++)?

i is not incremented: sizeof does not evaluate its operand (except for variable-length arrays); it only inspects the type at compile time.

How can you swap two variables without a temporary?

a ^= b; b ^= a; a ^= b; or a = a + b; b = a - b; a = a - b;. Both are curiosities: the XOR version fails if a and b are the same object (it zeroes it), and the arithmetic version can overflow. A temporary is clearer and just as fast.

What is the difference between #include guards and #pragma once?

Both stop a header from being processed twice in one translation unit. Guards (#ifndef X_H) are standard and work everywhere; #pragma once is shorter, avoids guard-name collisions, and is supported by GCC, Clang and MSVC, but is not in the standard.

Why is gets() dangerous and what replaces it?

gets reads a line into a buffer without knowing the buffer’s size, so any long input overflows it — it was the vector of the 1988 Morris worm. It was removed in C11. Use fgets(buf, sizeof buf, stdin) (and strip the newline).

What is a memory-mapped register and how do you access it in C?

A hardware device register exposed at a fixed physical address. Access it through a pointer to volatile of the right width: #define GPIO_OUT (*(volatile uint32_t *)0x40020014u), then GPIO_OUT |= 1u << 5;. volatile ensures every access actually reaches the hardware.

What happens when you write int *p = malloc(10); p[10] = 1;?

Undefined behaviour twice over: malloc(10) gives 10 bytes (2 ints on a 4-byte-int system, not 10 ints), and index 10 is far past the end. It may corrupt allocator metadata and crash later. Correct: int *p = malloc(10 * sizeof *p); and indexes 0–9.

Does C use name mangling?

C has no name mangling: the symbol for int add(int, int) is just add (sometimes _add). That is why C functions can’t be overloaded, and why C++ code calling C uses extern "C" to turn off C++ mangling.
