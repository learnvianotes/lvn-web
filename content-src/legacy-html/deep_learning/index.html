What Is Deep Learning?

Deep learning is machine learning with neural networks of many layers that learn their own features from raw data — pixels, audio samples, characters — instead of relying on hand-crafted ones.

Deep learning — a family of ML methods that stack many simple, differentiable layers. Each layer transforms its input into a slightly more useful representation; the whole stack is trained end-to-end with gradient descent.

In classic ML (see the Machine Learning notes) a person designs the features — word counts, edge histograms, ratios — and a model such as a random forest learns from them. A deep network learns the features too: early layers of an image model detect edges, middle layers textures and parts, late layers whole objects.

A network is a stack of functions

Each layer is a matrix multiply plus a non-linearity. Stacking them turns a raw input vector into a prediction:

Python
import numpy as np

rng = np.random.default_rng(0)
x = rng.normal(size=(1, 784))                  # one 28×28 image, flattened
W1, W2, W3 = rng.normal(size=(784, 128)), rng.normal(size=(128, 64)), rng.normal(size=(64, 10))

h1 = np.maximum(0, x @ W1)                     # layer 1: 784 → 128 features
h2 = np.maximum(0, h1 @ W2)                    # layer 2: 128 → 64 features
logits = h2 @ W3                               # output: 64 → 10 class scores
print(h1.shape, h2.shape, logits.shape)        # (1, 128) (1, 64) (1, 10)
print(W1.size + W2.size + W3.size)             # 109184   ← weights to learn (biases left out)

Why now?

Data

The web, phones and sensors produced labelled datasets such as ImageNet (1.2 M images) and huge text corpora.

Compute

GPUs do thousands of matrix multiplies in parallel; AlexNet (2012) trained on two gaming GPUs.

Algorithms

ReLU, good initialisation, dropout, BatchNorm, Adam, residual connections, attention — tricks that make deep stacks trainable.

Software

PyTorch, TensorFlow and JAX compute gradients automatically, so a new model is a few dozen lines.

Watch out

Deep learning is not automatically the best choice. On small tabular datasets, gradient-boosted trees (XGBoost, LightGBM) usually match or beat a neural network with far less effort.

When would you not use deep learning?

When data is small or tabular, when you need a simple interpretable model (credit decisions, regulated settings), or when compute and latency budgets are tight. Start with a simple baseline; reach for deep learning when the data is unstructured or plentiful — or when a pretrained model can be fine-tuned.

What does “deep” mean?

Many layers between input and output. Depth lets the network build features hierarchically — edges → textures → parts → objects — which is far more parameter-efficient than one enormous layer.

The Neuron & Perceptron

An artificial neuron takes a weighted sum of its inputs, adds a bias and passes the result through an activation function. The perceptron is the oldest version — and its failure on XOR explains why we need hidden layers.

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b = w · x + b a = f(z)
PartRole
Inputs xFeatures (pixel values, measurements, outputs of the previous layer)
Weights wHow much each input matters — learned
Bias bShifts the threshold — lets the neuron fire even when all inputs are 0
Activation fA non-linearity (step, sigmoid, ReLU…) applied to the sum z
Python
import numpy as np

x = np.array([0.5, -1.0, 2.0])     # inputs
w = np.array([0.4, 0.3, -0.2])     # weights
b = 0.1                            # bias

z = w @ x + b                      # weighted sum: 0.2 - 0.3 - 0.4 + 0.1
a = 1 / (1 + np.exp(-z))           # sigmoid activation
print(round(z, 2), round(a, 3))    # -0.4 0.401
The perceptron learning rule

Rosenblatt's perceptron (1958) uses a step activation (output 1 if z > 0, else 0) and a simple rule: after each example, nudge the weights toward the right answer.

w ← w + η (y − ŷ) x b ← b + η (y − ŷ)
Python
import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]])

def train_perceptron(X, y, epochs=20, lr=0.1):
    w, b = np.zeros(2), 0.0
    for _ in range(epochs):
        for xi, yi in zip(X, y):
            pred = int(xi @ w + b > 0)
            w += lr * (yi - pred) * xi          # no change when the prediction is right
            b += lr * (yi - pred)
    return (X @ w + b > 0).astype(int).tolist()

print(train_perceptron(X, np.array([0, 0, 0, 1])))       # [0, 0, 0, 1] ← AND: learned
print(train_perceptron(X, np.array([0, 1, 1, 1])))       # [0, 1, 1, 1] ← OR: learned
print(train_perceptron(X, np.array([0, 1, 1, 0]), 1000)) # [1, 1, 0, 0] ← XOR: wrong, whatever the epochs
Why XOR breaks it

A single neuron draws one straight line (a hyperplane) through the input space. AND and OR are linearly separable; XOR is not — no single line puts (0,1) and (1,0) on one side and (0,0), (1,1) on the other. Minsky & Papert's 1969 book made this point and helped cause the first “AI winter”.

Key point

The fix is a hidden layer: two neurons each draw a line, and a third combines them. That is a multi-layer perceptron (next topics), trained with backpropagation.

Biological neuronArtificial neuron
InputsDendrites receive signalsNumbers x₁…xₙ
IntegrationCell body sums chargeWeighted sum w · x + b
FiringSpikes past a thresholdActivation function f(z)
Watch out

The biological analogy is loose inspiration only. Modern networks are best understood as differentiable functions optimised by gradient descent.

What is the role of the bias term?

Without it, w · x is 0 whenever x is 0, so the decision boundary must pass through the origin. The bias shifts the boundary (or the activation's threshold), giving the neuron one more degree of freedom.

Can a single perceptron learn XOR?

No. It can only separate classes with a straight line, and XOR isn't linearly separable. One hidden layer with a non-linear activation is enough.

Activations add the non-linearity that lets networks learn curved decision boundaries. Without them, any stack of layers collapses into one linear layer.

import numpy as np
from math import erf, sqrt

z = np.array([-2.0, 0.0, 2.0])
sigmoid = 1 / (1 + np.exp(-z))
tanh = np.tanh(z)
relu = np.maximum(0, z)
leaky = np.where(z > 0, z, 0.01 * z)
gelu = z * 0.5 * (1 + np.array([erf(v / sqrt(2)) for v in z]))

print(sigmoid.round(3).tolist())    # [0.119, 0.5, 0.881]
print(tanh.round(3).tolist())       # [-0.964, 0.0, 0.964]
print(relu.tolist())                # [0.0, 0.0, 2.0]
print(leaky.tolist())               # [-0.02, 0.0, 2.0]
print(gelu.round(3).tolist())       # [-0.046, 0.0, 1.954]
Derivatives — why ReLU won

Backprop multiplies one activation derivative per layer. Sigmoid's derivative is at most 0.25, so ten sigmoid layers can shrink a gradient by 0.25¹⁰ ≈ 10⁻⁶. ReLU's derivative is exactly 1 for positive inputs, so gradients pass through unchanged.

Python
import numpy as np

z = np.array([-4.0, 0.0, 4.0])
s = 1 / (1 + np.exp(-z))
print((s * (1 - s)).round(4).tolist())     # [0.0177, 0.25, 0.0177] ← σ'(z) = σ(z)(1 − σ(z)); max 0.25
print((1 - np.tanh(z) ** 2).round(4).tolist())   # [0.0013, 1.0, 0.0013] ← tanh'(z); max 1
print((z > 0).astype(float).tolist())      # [0.0, 0.0, 1.0] ← ReLU'(z)
print(0.25 ** 10)                          # 9.5367431640625e-07 ← best case after 10 sigmoid layers
Softmax, safely

Softmax turns a vector of scores (logits) into probabilities. Subtracting the maximum first gives the same answer (it cancels in the ratio) but prevents exp from overflowing.

Python
import numpy as np

def softmax(z):
    e = np.exp(z - z.max())            # shift so the largest exponent is e^0 = 1
    return e / e.sum()

logits = np.array([2.0, 1.0, 0.1])
p = softmax(logits)
print(p.round(3).tolist(), round(p.sum(), 6))    # [0.659, 0.242, 0.099] 1.0

big = np.array([1000.0, 999.0, 998.1])           # same gaps, huge values
with np.errstate(over="ignore", invalid="ignore"):
    naive = np.exp(big) / np.exp(big).sum()
print(naive.tolist())                            # [nan, nan, nan] ← inf / inf
print(softmax(big).round(3).tolist())            # [0.659, 0.242, 0.099]

Do

Use ReLU (or GELU/SiLU) in hidden layers; pick the output activation from the task: none for regression, sigmoid for binary, softmax for multi-class.

Avoid

Sigmoid/tanh in the hidden layers of a deep feed-forward net — gradients vanish.

Why do we need non-linear activation functions?

A composition of linear maps is linear, so without non-linearities a 100-layer network could only learn what logistic/linear regression learns. Non-linearities let it approximate curved functions.

What is the dying ReLU problem?

If a unit's pre-activation becomes negative for every input (e.g. after a large update or a bad bias), its output and gradient are 0 everywhere and it never recovers. Fixes: lower learning rate, He initialisation, Leaky ReLU/GELU.

Sigmoid vs softmax at the output?

Sigmoid gives an independent probability per output — binary or multi-label (an image can be both “dog” and “outdoor”). Softmax gives a distribution over mutually exclusive classes that sums to 1 — multi-class.

MLPs & the Forward Pass

A multi-layer perceptron (MLP) stacks fully-connected layers with activations in between. The forward pass is just matrix multiplies — computed for a whole batch at once.

Fully-connected (dense / linear) layer — every output unit is connected to every input: Y = X W + b, where X is (batch, n_in), W is (n_in, n_out) and b is (n_out,).

Input layer (features)
→
Hidden layer 1 + ReLU
→
Hidden layer 2 + ReLU
→
Output layer (logits)
Shapes and parameter counts
parameters of a dense layer = n_in × n_out + n_out (weights + biases)
Python
import numpy as np

rng = np.random.default_rng(0)
sizes = [4, 16, 8, 3]                  # 4 features → 16 → 8 → 3 classes
params = [(rng.normal(0, 0.5, (a, b)), np.zeros(b)) for a, b in zip(sizes, sizes[1:])]

def forward(X):
    h = X
    for i, (W, b) in enumerate(params):
        h = h @ W + b
        if i < len(params) - 1:       # ReLU on hidden layers only
            h = np.maximum(0, h)
    return h                           # logits

X = rng.normal(size=(5, 4))            # a batch of 5 samples
print(forward(X).shape)                # (5, 3)
print(sum(W.size + b.size for W, b in params))   # 243 ← (4·16+16) + (16·8+8) + (8·3+3)
A hidden layer solves XOR

With hand-picked weights, two ReLU units are enough: h₁ = relu(x₁ + x₂) counts the ones, h₂ = relu(x₁ + x₂ − 1) fires only when both are 1, and the output is h₁ − 2h₂.

Python
import numpy as np

X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]])
W1 = np.array([[1, 1], [1, 1]]); b1 = np.array([0, -1])
W2 = np.array([1, -2]);          b2 = 0

H = np.maximum(0, X @ W1 + b1)
print(H.tolist())                  # [[0, 0], [1, 0], [1, 0], [2, 1]] ← the hidden representation
print((H @ W2 + b2).tolist())      # [0, 1, 1, 0] ← XOR
Key point

The hidden layer re-maps the inputs so that the classes become linearly separable — (0,1) and (1,0) both land on [1, 0]. That is what “learning a representation” means. Backpropagation finds such weights automatically (see Backpropagation).

Universal approximation

Universal approximation theorem — an MLP with one hidden layer and a non-linear activation can approximate any continuous function on a bounded domain as closely as you like — given enough hidden units.

Watch out

The theorem says a good network exists, not that gradient descent will find it or that it will generalise. The required width can be astronomically large; in practice depth gives the same power with far fewer parameters.

ChoiceRule of thumb
Hidden layers1–3 for tabular data; deeper nets need tricks (normalisation, residuals)
WidthPowers of two (64, 128, 256…) — wide enough to overfit a small batch
Hidden activationReLU / GELU
Output layerLinear, with n_out = 1 (regression / binary) or number of classes
What happens in a forward pass?

Input flows layer by layer: each layer computes XW + b, applies its activation and passes the result on, until the output layer produces predictions (logits). Intermediate activations are kept in memory because backprop needs them.

How many parameters does a Linear(512, 256) layer have?

512 × 256 + 256 = 131,328 — one weight per input–output pair plus one bias per output.

MSE = (1/n) Σ (yᵢ − ŷᵢ)² MAE = (1/n) Σ |yᵢ − ŷᵢ|
Python
import numpy as np

y     = np.array([3.0, 5.0, 2.0, 8.0])
y_hat = np.array([2.5, 5.0, 3.0, 4.0])      # the last prediction is badly off

err = y - y_hat
print(np.mean(err ** 2))                    # 4.3125 ← MSE: the outlier dominates (4² = 16)
print(np.mean(np.abs(err)))                 # 1.375 ← MAE: every unit of error counts the same

MSE punishes large errors quadratically (good when big mistakes are very bad, bad when labels contain outliers). MAE is robust to outliers but its gradient doesn't shrink near the optimum. Huber is quadratic for small errors and linear for large ones — a compromise.

Binary cross-entropy
BCE = −(1/n) Σ [ yᵢ log pᵢ + (1 − yᵢ) log(1 − pᵢ) ] p = σ(logit)
Python
import numpy as np

def bce(y, p):
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

y = np.array([1, 0, 1])
print(round(bce(y, np.array([0.9, 0.1, 0.8])), 4))    # 0.1446 ← confident and right
print(round(bce(y, np.array([0.1, 0.9, 0.2])), 4))    # 2.0715 ← confident and wrong: huge loss
Cross-entropy for multi-class
CE = −log p_true = −log softmax(z)_true = −z_true + log Σⱼ e^zⱼ

Cross-entropy only looks at the probability given to the correct class. Predicting 0.7 for the right class costs −log 0.7 ≈ 0.36; predicting 0.01 costs 4.6. With k classes, a model that guesses uniformly scores log k — a handy sanity check for the first loss you see.

Python
import numpy as np
import torch
from torch import nn

logits = np.array([[2.0, 1.0, 0.1],       # sample 0: true class 0
                   [0.5, 2.5, 0.3]])      # sample 1: true class 1
target = np.array([0, 1])

log_probs = logits - np.log(np.exp(logits).sum(axis=1, keepdims=True))   # log-softmax
ce = -log_probs[np.arange(2), target].mean()
print(round(ce, 4))                                            # 0.3185

loss_fn = nn.CrossEntropyLoss()                               # log-softmax + NLL in one stable op
print(round(loss_fn(torch.tensor(logits), torch.tensor(target)).item(), 4))   # 0.3185
print(round(np.log(3), 4))                                    # 1.0986 ← loss of a uniform guess over 3 classes

Python

Watch out

nn.CrossEntropyLoss and nn.BCEWithLogitsLoss apply softmax/sigmoid internally. Adding your own softmax/sigmoid before them squashes the gradients and training stalls. Apply softmax only when you need probabilities for display or decisions.

Why cross-entropy instead of MSE for classification?

Cross-entropy is the negative log-likelihood of the correct class, so it punishes confident wrong answers heavily and its gradient with softmax is simply p − y — large when wrong. MSE on sigmoid/softmax outputs gives tiny gradients when the output saturates, so learning is slow.

What loss would you expect at the start of training a 10-class classifier?

About ln 10 ≈ 2.30. Much higher means the initial logits are too large (bad init or a bug); it's one of the quickest sanity checks.

Gradient Descent

Training = walking downhill on the loss surface. The gradient points uphill, so each step moves the weights a little in the opposite direction.

θ ← θ − η · ∇θ L(θ) η = learning rate

In deep learning “SGD” almost always means mini-batch SGD. Vocabulary: one iteration (step) processes one batch; one epoch is a full pass over the data — ceil(N / batch_size) iterations.

Mini-batch GD from scratch
Python
import numpy as np

rng = np.random.default_rng(0)
X = rng.uniform(-1, 1, size=200)
y = 3 * X + 2 + rng.normal(0, 0.1, size=200)     # true line: y = 3x + 2

w, b, lr, batch = 0.0, 0.0, 0.1, 20
for epoch in range(50):
    idx = rng.permutation(len(X))                 # reshuffle every epoch
    for start in range(0, len(X), batch):
        j = idx[start:start + batch]
        err = (w * X[j] + b) - y[j]
        w -= lr * 2 * np.mean(err * X[j])         # ∂MSE/∂w
        b -= lr * 2 * np.mean(err)                # ∂MSE/∂b

print(round(w, 2), round(b, 2))                   # 2.99 2.0
print(len(X) // batch * 50)                       # 500 ← updates made (10 per epoch × 50 epochs)
The learning rate
Python
def descend(lr, steps=20, w=5.0):
    for _ in range(steps):
        w -= lr * 2 * w            # minimise f(w) = w², gradient 2w
    return w

print(round(descend(0.01), 3))     # 3.338 ← too small: barely moved
print(round(descend(0.1), 3))      # 0.058 ← good: close to the minimum at 0
print(round(descend(1.1), 1))      # 191.7 ← too large: diverges
SymptomLikely cause

Key point

Typical starting points: 1e-3 for Adam/AdamW, 0.1 for SGD with momentum on CNNs. If you change the batch size a lot, retune the learning rate (a common heuristic scales it linearly with the batch size).

Watch out

The loss surface of a deep network is not a bowl — it has saddle points, flat regions and many minima. Mini-batch noise actually helps: it keeps the optimiser moving through flat areas and tends to find wider minima that generalise better.

What is the difference between an epoch, a batch and an iteration?

A batch is the subset of examples used for one gradient step; an iteration is one such step; an epoch is one pass over the whole training set. With 10,000 examples and batch size 100, one epoch is 100 iterations.

How does batch size affect training?

Bigger batches give smoother gradients and better GPU utilisation but need more memory, often a larger learning rate, and can generalise slightly worse. Smaller batches are noisier (a mild regulariser) but slower per epoch.

Training Neural Networks

Backpropagation

Backpropagation computes the gradient of the loss with respect to every weight in one backward sweep, reusing intermediate results via the chain rule. It's what makes training deep networks affordable.

Backpropagation — reverse-mode automatic differentiation: run the forward pass and remember the intermediate values, then walk the computational graph backwards, multiplying each node's local gradient by the gradient flowing in from above.

chain rule: ∂L/∂w = ∂L/∂a · ∂a/∂z · ∂z/∂w
A computational graph by hand

One neuron with a squared-error loss: z = w·x + b, a = σ(z), L = (a − y)².

x, w, b
→
z = w·x + b
→
a = σ(z)
→
L = (a − y)²
Python
import math

x, y, w, b = 2.0, 1.0, 0.5, -0.5
# forward
z = w * x + b                           # 0.5
a = 1 / (1 + math.exp(-z))              # σ(0.5)
L = (a - y) ** 2
# backward — one local derivative per edge, multiplied right to left
dL_da = 2 * (a - y)
da_dz = a * (1 - a)
dL_dz = dL_da * da_dz
dL_dw = dL_dz * x                       # ∂z/∂w = x
dL_db = dL_dz * 1                       # ∂z/∂b = 1
print(round(L, 4), round(dL_dw, 4), round(dL_db, 4))   # 0.1425 -0.3549 -0.1774

PyTorch's autograd does exactly this bookkeeping for you:

Python

A 2-layer network from scratch

Forward: H = relu(X W₁ + b₁), P = σ(H W₂ + b₂), BCE loss. Backward, the key results are: for sigmoid + BCE, ∂L/∂logits = (P − y) / n; for a linear layer Y = XW, ∂L/∂W = Xᵀ · ∂L/∂Y and ∂L/∂X = ∂L/∂Y · Wᵀ; for ReLU, pass the gradient where the input was positive.

Python
import numpy as np

rng = np.random.default_rng(0)
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], dtype=float)
y = np.array([[0], [1], [1], [0]], dtype=float)              # XOR

params = {"W1": rng.normal(0, 1, (2, 8)), "b1": np.full(8, 0.1),
          "W2": rng.normal(0, 1, (8, 1)), "b2": np.zeros(1)}

def forward_backward(p):
    Z1 = X @ p["W1"] + p["b1"]; H = np.maximum(0, Z1)       # forward
    Z2 = H @ p["W2"] + p["b2"]; P = 1 / (1 + np.exp(-Z2))
    loss = -np.mean(y * np.log(P) + (1 - y) * np.log(1 - P))
    dZ2 = (P - y) / len(X)                                   # backward
    dW2, db2 = H.T @ dZ2, dZ2.sum(0)
    dH = dZ2 @ p["W2"].T
    dZ1 = dH * (Z1 > 0)
    dW1, db1 = X.T @ dZ1, dZ1.sum(0)
    return loss, {"W1": dW1, "b1": db1, "W2": dW2, "b2": db2}

loss, grads = forward_backward(params)
print(round(loss, 4))                     # 0.7371 ← before training
Gradient checking

Always verify a hand-written backward pass numerically. Nudge each weight by ±ε and compare the slope of the loss with the analytic gradient:

∂L/∂θ ≈ [ L(θ + ε) − L(θ − ε) ] / 2ε relative error = |g_analytic − g_numeric| / (|g_analytic| + |g_numeric|)

Key point

Cost: the backward pass costs roughly 2× the forward pass, and it needs the stored activations — which is why training uses much more memory than inference.

Watch out

Gradient checking is for debugging only — it costs two forward passes per parameter. Use float64, a small ε (~1e-6) and avoid points where ReLU is exactly at its kink.

Explain backpropagation in two sentences.

After a forward pass that stores intermediate values, we apply the chain rule backwards from the loss: each node multiplies the incoming gradient by its local derivative and passes it to its inputs. This gives the gradient for every parameter in about the cost of one extra forward pass.

Why reverse mode and not forward mode differentiation?

A network has millions of inputs (parameters) and one scalar output (the loss). Reverse mode gets all parameter gradients in one backward pass; forward mode would need one pass per parameter.

Racing them on a narrow valley

f(x, y) = x² + 100y² is steep in y and flat in x — like many real loss surfaces. Plain SGD must keep its step below 0.01 to avoid bouncing out of the valley in y, and then crawls along x. All three start at (5, 1) and take 100 steps; the minimum is f = 0.

Python
import numpy as np

grad = lambda t: np.array([2 * t[0], 200 * t[1]])     # ∇ of f = x² + 100y²
f = lambda t: t[0] ** 2 + 100 * t[1] ** 2
start, steps = np.array([5.0, 1.0]), 100

def sgd(lr=0.009):                                    # above 0.01 it diverges in y
    t = start.copy()
    for _ in range(steps):
        t -= lr * grad(t)
    return f(t)

def momentum(lr=0.005, beta=0.9):
    t, v = start.copy(), np.zeros(2)
    for _ in range(steps):
        v = beta * v + grad(t)
        t -= lr * v
    return f(t)

def adam(lr=0.3, b1=0.9, b2=0.999, eps=1e-8):
    t, m, v = start.copy(), np.zeros(2), np.zeros(2)
    for k in range(1, steps + 1):
        g = grad(t)
        m = b1 * m + (1 - b1) * g
        v = b2 * v + (1 - b2) * g ** 2
        m_hat, v_hat = m / (1 - b1 ** k), v / (1 - b2 ** k)
        t -= lr * m_hat / (np.sqrt(v_hat) + eps)
    return f(t)

print(f"{sgd():.4f}")        # 0.6611 ← still far from the minimum
print(f"{momentum():.4f}")   # 0.0004
print(f"{adam():.4f}")       # 0.0007

Adam vs AdamW

L2 regularisation adds λθ to the gradient. In Adam that term is then divided by √v̂, so parameters with large gradients get less regularisation — not what we want. AdamW applies the decay directly to the weights, outside the adaptive step. It's the default for Transformers.

Watch out

An optimizer keeps state: Adam stores two extra tensors (m, v) per parameter — the model's weights ×3 in memory. Save the optimizer's state_dict() with checkpoints or resumed training will behave differently.

Why does Adam need bias correction?

m and v start at zero, so during the first steps they're biased toward zero (e.g. after step 1, m = 0.1·g). Dividing by 1 − βᵗ rescales them to proper averages; the correction fades as t grows.

What does momentum do?

It keeps an exponentially-weighted running sum of past gradients. Components that point the same way every step add up (faster progress along valleys); components that flip sign cancel (less zig-zagging).

from torch import nn

def lrs(make_scheduler, epochs=8):
    opt = torch.optim.SGD(nn.Linear(2, 1).parameters(), lr=0.1)
    sched = make_scheduler(opt)
    out = []
    for _ in range(epochs):

        sched.step()                  # then advance the schedule
    return out

Warmup + cosine

Adam's early estimates of v are noisy, and a freshly initialised network has large, badly-scaled gradients. Starting with a tiny LR and ramping up over the first few hundred or thousand steps avoids early divergence.

Python
import math
import torch
from torch import nn

warmup, total = 3, 10
def factor(step):                                   # multiplier on the base LR
    if step < warmup:
        return (step + 1) / warmup                  # linear ramp
    progress = (step - warmup) / (total - warmup)
    return 0.5 * (1 + math.cos(math.pi * progress)) # cosine down to 0

opt = torch.optim.AdamW(nn.Linear(2, 1).parameters(), lr=1e-3)
sched = torch.optim.lr_scheduler.LambdaLR(opt, factor)
seen = []
for _ in range(total):
    seen.append(round(opt.param_groups[0]["lr"] * 1000, 2))   # in units of 1e-3
    opt.step(); sched.step()
print(seen)     # [0.33, 0.67, 1.0, 1.0, 0.95, 0.81, 0.61, 0.39, 0.19, 0.05]
Watch out

Call scheduler.step() after optimizer.step(), and be consistent about the unit — per epoch or per batch. Transformers usually step the schedule every batch; ReduceLROnPlateau.step(val_loss) takes the metric as an argument.

Finding a good max LR

An LR range test: train for a few hundred steps while increasing the LR exponentially (1e-7 → 1), plot loss vs LR, and pick a value about 10× smaller than where the loss is lowest (before it blows up).

Why use learning-rate warmup?

At the start, weights are random and optimizer statistics are unreliable, so large steps can push the network into a bad region or cause nans. A short linear warmup lets things stabilise before the full learning rate kicks in; it matters most for Transformers, Adam and large batch sizes.

Why decay the learning rate?

A large LR explores and makes fast progress but bounces around the minimum; lowering it lets the weights settle into the bottom of the basin, which usually lowers both training and validation loss at the end.

Stable Training & Regularization

Vanishing Gradients & Weight Init

In a deep network the signal is multiplied by one weight matrix per layer — forwards and backwards. If each multiplication shrinks it a little, gradients vanish; if each grows it a little, they explode. Good initialisation keeps the scale steady.

Why not start from zero?

If every weight in a layer starts equal, every unit computes the same output and receives the same gradient — they stay identical forever (symmetry). Random initialisation breaks the tie; the question is how large the random values should be.

Vanishing and exploding gradients

By the chain rule, the gradient at layer 1 is a product of one factor per layer above it. Factors below 1 (saturated sigmoids: slope ≤ 0.25) shrink it exponentially — early layers stop learning. Factors above 1 (large weights, long RNN unrolls) blow it up — the loss becomes nan.

Python
import torch
from torch import nn

def first_layer_grad(act, he=False, depth=15):
    torch.manual_seed(0)
    layers = []
    for _ in range(depth):
        lin = nn.Linear(32, 32)
        if he:
            nn.init.kaiming_normal_(lin.weight, nonlinearity="relu")
        layers += [lin, act()]
    net = nn.Sequential(*layers, nn.Linear(32, 1))
    net(torch.randn(64, 32)).pow(2).mean().backward()
    return net[0].weight.grad.abs().mean().item()

print(f"{first_layer_grad(nn.Sigmoid):.0e}")        # 3e-15 ← sigmoid: vanished
print(f"{first_layer_grad(nn.ReLU):.0e}")           # 2e-10 ← ReLU, default init: still shrinks

Key point

Clipping rescales the whole gradient vector when its norm exceeds max_norm — the direction is kept, only the step length is capped. Call it between loss.backward() and optimizer.step(). It's standard for RNNs and Transformers (max_norm=1.0).

What is the vanishing gradient problem and how do you fix it?

Gradients shrink exponentially as they flow backwards through many layers (or time steps) because they're multiplied by factors smaller than 1, so early layers barely learn. Fixes: ReLU-type activations, He/Xavier init, normalisation layers, residual connections, and gated RNNs (LSTM/GRU).

Why can't all weights be initialised to zero?

Every unit in a layer would compute the same function and get the same update, so the layer behaves like a single unit forever. (Biases can start at zero — the random weights already break the symmetry.)

Train vs eval mode

During training BatchNorm uses the current batch's mean and variance and updates running averages. In model.eval() it uses those running averages instead, so a single example gets a deterministic output.

Watch out

Forgetting model.eval() before validation or inference is a classic bug: BatchNorm then normalises with the statistics of whatever batch you pass in (and a batch of 1 breaks it), and dropout stays on. Always switch modes.

Each row is normalised on its own, so it works with any batch size (even 1) and with variable-length sequences — why Transformers use it. Many LLMs use RMSNorm, a cheaper variant that only divides by the root-mean-square (no mean subtraction).

GroupNorm

Normalises groups of channels per sample — a BatchNorm replacement for tiny batches (detection, segmentation).

Pre-LN vs Post-LN

Transformers normalise before each sub-layer (Pre-LN) in most modern models — more stable to train than the original Post-LN.

Why does batch normalization help?

It keeps each layer's inputs in a well-scaled range, which allows higher learning rates, reduces sensitivity to initialisation and smooths the loss landscape. The batch noise also gives a mild regularising effect.

BatchNorm vs LayerNorm — when do you use which?

BatchNorm for CNNs with reasonably large batches. LayerNorm (or RMSNorm) for Transformers and RNNs, where sequence lengths vary, batches can be small, and train/inference behaviour should be identical.

Stable Training & Regularization

Regularization

Big networks can memorise their training set. Regularisation makes memorising harder or less attractive, so the model learns patterns that generalise: weight decay, dropout, early stopping, data augmentation and more.

First diagnose (see the Machine Learning notes on train/test protocols): training loss far below validation loss means overfitting → regularise or get more data. Both losses high means underfitting → bigger model, train longer, less regularisation.

L2 regularisation / weight decay
L_total = L_data + (λ/2) Σ w² ⇒ w ← w − η(∇L_data + λw) = (1 − ηλ)·w − η∇L_data

Each step shrinks (“decays”) every weight towards zero; only weights that keep earning their place in the loss stay large. Smaller weights mean a smoother function. In PyTorch: AdamW(..., weight_decay=0.01); it's usual to exclude biases and normalisation parameters.

Dropout

During training, dropout zeroes each activation with probability p and scales the survivors by 1/(1−p) (inverted dropout), so the expected value is unchanged and nothing needs rescaling at test time. The network can't rely on any single unit — like training an ensemble of thinned networks.

Python

How does dropout work, and what changes at test time?

During training each unit is zeroed with probability p and the rest are scaled by 1/(1−p), so the network learns redundant features and can't depend on any one unit. At test time dropout is switched off (model.eval()); thanks to the inverted scaling no further adjustment is needed.

L2 regularisation vs weight decay — are they the same?

For plain SGD, yes: adding λw to the gradient is the same as shrinking the weights each step. For adaptive optimisers like Adam they differ, because the L2 term gets divided by the adaptive denominator. AdamW implements true (decoupled) weight decay.

Your model has 99% training accuracy and 70% validation accuracy. What do you do?

It's overfitting. Get more data or augment it, add weight decay/dropout, use early stopping, reduce model size, or start from a pretrained model. Also check the validation set comes from the same distribution and there's no leakage or label noise.

Autograd

Set requires_grad=True on a tensor and PyTorch records every operation on it in a graph. loss.backward() walks that graph backwards and stores ∂loss/∂x in x.grad.

Python

loss.backward()

loss.backward()

Why do we call zero_grad() every iteration?

PyTorch adds new gradients to whatever is in .grad (useful for gradient accumulation across micro-batches). Without resetting, each step would use the sum of all past gradients.

view vs reshape?

view never copies — it needs the tensor's memory to be laid out compatibly (contiguous) and errors otherwise. reshape returns a view when it can and copies when it must.

The Training Loop

Every PyTorch project has the same heartbeat: for each batch — forward, loss, zero_grad, backward, step. Around it: an evaluation loop in eval() mode under no_grad(), and checkpoints.

1
model.train()
Dropout on, BatchNorm uses batch statistics.
2
Forward
logits = model(xb) then loss = loss_fn(logits, yb).
3
optimizer.zero_grad()
Clear gradients from the previous step.
4
loss.backward()
Compute gradients.
5
optimizer.step()
Update weights (then scheduler.step() if you use one).
6
Evaluate
model.eval() + torch.no_grad() on the validation set; keep the best checkpoint.
A complete example

Classify points by whether they lie inside a circle — a non-linear boundary a linear model can't learn.

Python
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(0)
X = torch.rand(1000, 2) * 2 - 1                      # points in [-1, 1]²
y = ((X ** 2).sum(dim=1) < 0.5).long()               # class 1 inside the circle
train_ds, val_ds = TensorDataset(X[:800], y[:800]), TensorDataset(X[800:], y[800:])
train_loader = DataLoader(train_ds, batch_size=32, shuffle=True)
val_loader = DataLoader(val_ds, batch_size=200)

model = nn.Sequential(nn.Linear(2, 32), nn.ReLU(), nn.Linear(32, 32), nn.ReLU(), nn.Linear(32, 2))
loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-2)

def evaluate(loader):
    model.eval()
    correct = total = 0
    with torch.no_grad():
        for xb, yb in loader:
            correct += (model(xb).argmax(dim=1) == yb).sum().item()
            total += len(yb)
    return correct / total

for epoch in range(20):
    model.train()
    for xb, yb in train_loader:
        loss = loss_fn(model(xb), yb)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

print(f"train acc {evaluate(train_loader):.2f}, val acc {evaluate(val_loader):.2f}")   # train acc 0.99, val acc 0.97

Walk me through a PyTorch training step.

Put the model in train mode, move the batch to the device, run the forward pass to get logits, compute the loss, call optimizer.zero_grad(), loss.backward() to compute gradients, optionally clip them, then optimizer.step() to update the weights (and step the LR scheduler).

What does model.eval() change?

It switches layers that behave differently at inference: dropout is disabled and BatchNorm uses its running statistics. It does not disable gradient tracking — that's what torch.no_grad() is for.

Why is accuracy misleading on imbalanced data?

If 99% of transactions are legitimate, predicting “legit” for everything scores 99% while catching zero fraud. Use per-class precision/recall, F1, PR-AUC and a confusion matrix instead.

What is perplexity?

The exponential of the average per-token cross-entropy of a language model. It's the effective number of equally likely choices the model is torn between at each step — lower is better.

Convolutional Networks

Convolutions, Padding, Stride & Pooling

A convolutional layer slides small learned filters over an image. Each filter detects one local pattern (an edge, a texture) everywhere in the image, using the same few weights at every position.

Why not a dense layer?

Locality

Nearby pixels are related; a 3×3 filter looks only at a small neighbourhood.

Weight sharing

The same filter is used at every position — far fewer parameters than connecting every pixel to every unit.

Translation equivariance

Shift the input and the feature map shifts the same way: a cat is detected wherever it is.

Hierarchy

Stacked layers see larger regions: edges → textures → parts → objects.

The operation

At each position, multiply the filter element-wise with the patch underneath and sum (deep-learning “convolution” is technically cross-correlation — the filter isn't flipped).

Python
import numpy as np

def conv2d(img, k):
    kh, kw = k.shape
    out = np.zeros((img.shape[0] - kh + 1, img.shape[1] - kw + 1))
    for i in range(out.shape[0]):
        for j in range(out.shape[1]):
            out[i, j] = np.sum(img[i:i + kh, j:j + kw] * k)
    return out

img = np.array([[0, 0, 0, 9, 9, 9]] * 5, dtype=float)    # dark left half, bright right half
vertical_edge = np.array([[-1, 0, 1],
                          [-1, 0, 1],
                          [-1, 0, 1]], dtype=float)     # Sobel-like filter

Pooling shrinks feature maps (less compute, bigger receptive field) and adds a little tolerance to small shifts. It has no parameters. Modern CNNs often use stride-2 convolutions instead, and end with global average pooling — one number per channel — before the classifier.

Receptive field

The receptive field is the patch of the input that can influence one output unit. Each 3×3 conv (stride 1) adds 2 pixels; each stride multiplies how fast later layers grow it.

Python
def receptive_field(layers):          # layers: list of (kernel, stride)
    rf, jump = 1, 1
    for k, s in layers:
        rf += (k - 1) * jump
        jump *= s
    return rf

print(receptive_field([(3, 1)] * 2))                 # 5 ← two 3×3 convs see 5×5 (like one 5×5)
print(receptive_field([(3, 1)] * 3))                 # 7 ← three see 7×7
print(receptive_field([(3, 1), (2, 2), (3, 1), (2, 2), (3, 1)]))   # 18 ← pooling speeds growth
Key point

Two stacked 3×3 convs see the same 5×5 area as one 5×5 conv but use 2·9 = 18 weights per channel pair instead of 25 — and add an extra non-linearity. That's VGG's key insight.

How do you compute the output size of a conv layer?

⌊(n + 2p − k)/s⌋ + 1. Example: 224×224 input, 7×7 kernel, padding 3, stride 2 → ⌊(224 + 6 − 7)/2⌋ + 1 = 112.

Why are CNNs better than MLPs for images?

They exploit image structure: local connectivity and weight sharing cut parameters by orders of magnitude, translation equivariance means a pattern is recognised anywhere, and stacking builds a feature hierarchy. An MLP on raw pixels has to learn every pattern separately at every position.

Residual connections

Residual block — instead of learning H(x) directly, the block learns the change F(x) = H(x) − x and outputs F(x) + x. If the best thing is to do nothing, it only has to push F to zero.

import torch
from torch import nn

class ResidualBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.body = nn.Sequential(
            nn.Conv2d(channels, channels, 3, padding=1, bias=False), nn.BatchNorm2d(channels), nn.ReLU(),
            nn.Conv2d(channels, channels, 3, padding=1, bias=False), nn.BatchNorm2d(channels),
        )

    def forward(self, x):
        return torch.relu(self.body(x) + x)          # the skip connection

torch.manual_seed(0)
block = ResidualBlock(8)
x = torch.randn(2, 8, 16, 16)
print(block(x).shape)                                # torch.Size([2, 8, 16, 16]) ← shape preserved so x can be added

nn.init.zeros_(block.body[4].weight)                 # zero the last BN's scale → F(x) = 0
print(torch.allclose(block(x), torch.relu(x)))       # True ← the block passes x straight through

Why it works: the gradient of F(x) + x with respect to x is ∂F/∂x + 1. The +1 path carries gradients straight back through any number of blocks, so early layers keep learning. When the shapes differ (more channels, stride 2), the shortcut uses a 1×1 conv to match them.

1×1 convolutions

Mix channels at each pixel without looking at neighbours — cheap way to shrink or expand channel count (bottlenecks in Inception/ResNet-50).

Depthwise-separable conv

A per-channel 3×3 conv followed by a 1×1 conv: ~8–9× fewer operations than a full 3×3 conv (MobileNet).

Why do residual connections help train very deep networks?

They give gradients an identity path (the +x), so they don't vanish through many layers, and they make it easy for extra layers to do nothing harmful (learn F = 0). Plain 56-layer nets trained worse than 20-layer ones; ResNets kept improving past 100 layers.

What does a 1×1 convolution do?

It's a linear layer applied at every pixel across channels: it changes the number of channels (e.g. 256 → 64) and mixes information between them, cheaply, without changing the spatial size.

Key point

The same recipe powers NLP: take a pretrained Transformer (BERT, an LLM) and fine-tune it — fully, or with parameter-efficient methods like LoRA, covered in the GenAI notes (Fine-Tuning & PEFT).

What is transfer learning and why does it work?

Reusing a model trained on a large dataset as the starting point for a new task. Early layers learn general features (edges, textures; or syntax in language models) that are useful across tasks, so the new task only needs to learn a small head or small adjustments — with much less data and compute.

Feature extraction vs fine-tuning?

Feature extraction freezes the pretrained network and trains only the new head — fast, safe for small datasets. Fine-tuning also updates some or all pretrained layers (with a lower learning rate) — better accuracy when you have more data or the domain differs.

The vanilla RNN
hₜ = tanh(W_x xₜ + W_h hₜ₋₁ + b) the same weights at every time step
Python
import numpy as np

rng = np.random.default_rng(0)
d_in, d_h, T = 3, 4, 5
W_x, W_h, b = rng.normal(0, 0.5, (d_in, d_h)), rng.normal(0, 0.5, (d_h, d_h)), np.zeros(d_h)
xs = rng.normal(size=(T, d_in))            # a sequence of 5 steps, 3 features each

h = np.zeros(d_h)
for x_t in xs:                             # unroll through time
    h = np.tanh(x_t @ W_x + h @ W_h + b)
print(h.shape, h.round(3).tolist())        # (4,) [0.403, -0.613, 0.626, 0.503] ← final state summarises the sequence

Training unrolls the loop and backpropagates through every step (backpropagation through time, BPTT). The gradient reaching step 1 has been multiplied by W_h and a tanh slope once per step — so over long sequences it vanishes (or explodes). A plain RNN effectively remembers only the last few steps.

Gates are sigmoid layers (outputs between 0 and 1) that decide what to erase, what to write and what to expose. import torch
from torch import nn

class SentimentLSTM(nn.Module):                 # many-to-one classifier
    def __init__(self, vocab, emb=32, hidden=64, classes=2):
        super().__init__()
        self.embed = nn.Embedding(vocab, emb, padding_idx=0)
        self.lstm = nn.LSTM(emb, hidden, batch_first=True, bidirectional=True)
        self.head = nn.Linear(2 * hidden, classes)     # forward + backward directions

    def forward(self, tokens):
        _, (h_n, _) = self.lstm(self.embed(tokens))
        return self.head(torch.cat([h_n[0], h_n[1]], dim=1))

torch.manual_seed(0)
model = SentimentLSTM(vocab=1000)
print(model(torch.randint(1, 1000, (4, 12))).shape)   # torch.Size([4, 2]) ← 4 reviews of 12 tokens
Watch out

RNNs process steps sequentially, so they can't parallelise over time and are slow on long sequences. For most language tasks Transformers replaced them; RNNs remain useful for streaming, small on-device models and some time-series work.

How does an LSTM solve the vanishing gradient problem?

Its cell state is updated additively (c = f·c + i·c̃) and controlled by gates. When the forget gate is near 1 the gradient flows back through the cell almost unchanged, instead of being squashed by a matrix and tanh at every step.

LSTM vs GRU?

GRU merges the cell and hidden state and uses two gates instead of three, so it has ~25% fewer parameters and trains faster. Performance is usually similar; LSTM can be better on very long dependencies.

Attention & Self-Attention

Attention lets every position look at every other position and take a weighted average of what it finds, with weights computed from the data. It's the core operation of Transformers.

The analogy is a soft dictionary lookup. Each token produces a query (what am I looking for?), a key (what do I contain?) and a value (what I'll hand over). A query is compared with every key; the softmax of those scores says how much of each value to take.

Attention(Q, K, V) = softmax( Q Kᵀ / √d_k ) V
1
Project
Q = X W_Q, K = X W_K, V = X W_V — three learned linear maps of the same input (that's what makes it self-attention).
2
Score
Q Kᵀ — dot product of every query with every key: an (n × n) matrix.
3
Scale
Divide by √d_k so the scores don't grow with the vector size.
4
Mask (optional)
Set forbidden scores to −∞ — future tokens in a decoder, padding.
5
Softmax
Row-wise: each token's weights over all tokens sum to 1.
6
Mix
Multiply by V: each output is a weighted average of value vectors.
From scratch
Python
import numpy as np

def softmax(z):
    e = np.exp(z - z.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def attention(Q, K, V, mask=None):
    scores = Q @ K.T / np.sqrt(K.shape[-1])
    if mask is not None:
        scores = np.where(mask, scores, -np.inf)
    weights = softmax(scores)
    return weights @ V, weights

rng = np.random.default_rng(0)
n, d_model, d_k = 4, 8, 8                      # 4 tokens
X = rng.normal(size=(n, d_model))
W_q, W_k, W_v = (rng.normal(0, d_model ** -0.5, (d_model, d_k)) for _ in range(3))
Q, K, V = X @ W_q, X @ W_k, X @ W_v

out, w = attention(Q, K, V)
print(out.shape, w.shape)                      # (4, 8) (4, 4) ← one output per token; n × n weights
print(w.sum(axis=1).round(6).tolist())         # [1.0, 1.0, 1.0, 1.0] ← each row sums to 1

causal = np.tril(np.ones((n, n), dtype=bool))  # token i may only look at tokens ≤ i
_, w_causal = attention(Q, K, V, mask=causal)

print(w_causal[0].round(2).tolist())           # [1.0, 0.0, 0.0, 0.0] ← token 0 can only attend to itself

Why divide by √d_k?
Python
import numpy as np

rng = np.random.default_rng(0)
for_d = {}
for d in (4, 64, 1024):
    q, k = rng.normal(size=(10000, d)), rng.normal(size=(10000, d))
    dots = (q * k).sum(axis=1)
    for_d[d] = (round(float(dots.std()), 1), round(float((dots / np.sqrt(d)).std()), 2))
print(for_d)       # {4: (2.0, 1.0), 64: (8.1, 1.01), 1024: (32.0, 1.0)} ← raw std ≈ √d; scaled std ≈ 1

Dot products of random d-dimensional vectors have standard deviation √d. Large scores push softmax into saturation — nearly one-hot, with vanishing gradients. Dividing by √d_k keeps the scores at unit scale.

Watch out

Attention compares every token with every other: time and memory grow as O(n²) in sequence length. Doubling the context quadruples the attention cost — the reason for FlashAttention, sparse/sliding-window attention and KV caching.

Explain self-attention.

Each token is projected into a query, key and value. A token's output is a weighted average of all value vectors, where the weights are the softmax of its query's (scaled) dot products with every key. This lets each token gather information from the most relevant other tokens, in parallel for the whole sequence.

Why is attention better than an RNN for long sequences?

Any two positions interact directly in one step (path length 1 instead of n), so long-range dependencies are easy to learn and gradients don't vanish across time; and all positions are processed in parallel on a GPU. The cost is O(n²) compute and memory in the sequence length.

Positional encoding

Attention is permutation-invariant — shuffle the tokens and each output is just shuffled too — so order must be injected. The original paper adds sinusoids of different frequencies to the embeddings; many models learn position embeddings, and modern LLMs use rotary embeddings (RoPE) applied inside attention.

import numpy as np

def positional_encoding(n_positions, d):
    pos = np.arange(n_positions)[:, None]
    i = np.arange(0, d, 2)[None, :]
    angle = pos / 10000 ** (i / d)
    pe = np.zeros((n_positions, d))
    pe[:, 0::2], pe[:, 1::2] = np.sin(angle), np.cos(angle)
    return pe

Instead of one attention with d_model-wide vectors, split into h heads of size d_model / h, attend in each independently, concatenate and project. Different heads learn different relations — one follows syntax, another coreference, another nearby tokens — at the same total cost.

A Transformer block
Python
import torch
from torch import nn

class TransformerBlock(nn.Module):
    """Pre-LN block, as in GPT-2 and most modern models."""
    def __init__(self, d_model=64, n_heads=4, d_ff=256, dropout=0.1):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(d_model, n_heads, dropout=dropout, batch_first=True)
        self.ff = nn.Sequential(nn.Linear(d_model, d_ff), nn.GELU(), nn.Linear(d_ff, d_model), nn.Dropout(dropout))

    def forward(self, x, causal=True):
        n = x.shape[1]
        mask = torch.triu(torch.ones(n, n, dtype=torch.bool), diagonal=1) if causal else None   # True = blocked
        h = self.ln1(x)
        x = x + self.attn(h, h, h, attn_mask=mask, need_weights=False)[0]   # residual 1
        x = x + self.ff(self.ln2(x))                                         # residual 2
        return x

torch.manual_seed(0)
block = TransformerBlock()
x = torch.randn(2, 10, 64)
print(block(x).shape)                                   # torch.Size([2, 10, 64]) ← same shape in and out: blocks stack
print(sum(p.numel() for p in block.parameters()))       # 49984

layer = nn.TransformerEncoderLayer(d_model=64, nhead=4, dim_feedforward=256, batch_first=True, norm_first=True)
encoder = nn.TransformerEncoder(layer, num_layers=6, enable_nested_tensor=False)   # built-in, 6 deep
print(encoder(x).shape)                                 # torch.Size([2, 10, 64])

Why Transformers won
  • Parallel training over all positions — unlike RNNs — so they use GPUs efficiently.
  • Direct long-range interactions between any two tokens.
  • Scale predictably: loss keeps falling as data, parameters and compute grow (scaling laws).

Watch out

Costs: attention is O(n²) in context length, and generation is sequential — one token at a time, with a KV cache storing past keys and values. Serving tricks (KV caching, quantisation, speculative decoding) are covered in the GenAI notes under LLM Optimization.

Walk through a Transformer layer.

Input vectors (token embeddings + positions) go through LayerNorm and multi-head self-attention, whose output is added back to the input (residual). Then another LayerNorm and a position-wise feed-forward network (two linear layers with GELU), again added residually. The shape is unchanged, so N such layers stack.

Why do Transformers need positional encodings?

Self-attention treats the input as a set — it has no notion of order. Positional encodings (sinusoidal, learned, or rotary) inject each token's position so “dog bites man” differs from “man bites dog”.

What is the purpose of multiple attention heads?

Each head attends in its own lower-dimensional subspace, so the layer can capture several kinds of relationships at once (syntax, coreference, position) for about the same cost as one full-width head.

Autoencoders & VAEs

An autoencoder squeezes its input through a narrow bottleneck and learns to rebuild it — so the bottleneck must capture what matters. A variational autoencoder (VAE) makes that bottleneck a smooth probability space you can sample new data from.

A plain autoencoder

Trained only to minimise reconstruction error ‖x − x̂‖² — no labels needed (self-supervised). Here the 10-D data secretly lives on a 2-D plane, and a 2-unit bottleneck is enough to rebuild it:

Python
import torch
from torch import nn

torch.manual_seed(0)
basis = torch.randn(2, 10)
X = torch.randn(512, 2) @ basis                   # 512 points in 10-D that lie on a 2-D plane

encoder = nn.Sequential(nn.Linear(10, 32), nn.ReLU(), nn.Linear(32, 2))
decoder = nn.Sequential(nn.Linear(2, 32), nn.ReLU(), nn.Linear(32, 10))
params = list(encoder.parameters()) + list(decoder.parameters())
opt = torch.optim.Adam(params, lr=1e-2)

for step in range(1000):
    loss = ((decoder(encoder(X)) - X) ** 2).mean()
    opt.zero_grad(); loss.backward(); opt.step()

print(encoder(X).shape)                                 # torch.Size([512, 2]) ← 10 numbers compressed to 2
print(round(X.var().item(), 2), loss.item() < 0.05)     # 2.46 True ← data variance vs reconstruction error

Variational autoencoder

The VAE encoder outputs a distribution — a mean μ and a standard deviation σ per latent dimension. We sample z from it, decode, and add a penalty that keeps every such distribution close to a standard normal N(0, I). The latent space becomes smooth and filled in, so decoding z ~ N(0, I) produces new, plausible data.

loss = reconstruction(x, x̂) + KL( N(μ, σ²) ‖ N(0, 1) ) KL = ½ Σ ( μ² + σ² − log σ² − 1 )

Reparameterisation trick — sampling isn't differentiable, so write z = μ + σ ⊙ ε with ε ~ N(0, I). The randomness sits in ε; gradients flow through μ and σ.

Python
import torch
from torch import nn
import torch.nn.functional as F

class VAE(nn.Module):
    def __init__(self, d_in=784, d_hidden=256, d_latent=16):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(d_in, d_hidden), nn.ReLU())
        self.mu = nn.Linear(d_hidden, d_latent)
        self.log_var = nn.Linear(d_hidden, d_latent)       # predict log σ² — any real number is valid
        self.dec = nn.Sequential(nn.Linear(d_latent, d_hidden), nn.ReLU(), nn.Linear(d_hidden, d_in))

    def forward(self, x):
        h = self.enc(x)
        mu, log_var = self.mu(h), self.log_var(h)
        z = mu + torch.exp(0.5 * log_var) * torch.randn_like(mu)   # reparameterisation
        return self.dec(z), mu, log_var

def vae_loss(logits, x, mu, log_var):
    recon = F.binary_cross_entropy_with_logits(logits, x, reduction="sum") / len(x)
    kl = 0.5 * (mu ** 2 + log_var.exp() - log_var - 1).sum() / len(x)
    return recon + kl, kl

torch.manual_seed(0)
vae = VAE()
x = torch.rand(8, 784)                                # a batch of 8 "images" with pixels in [0, 1]
logits, mu, log_var = vae(x)
loss, kl = vae_loss(logits, x, mu, log_var)
print(logits.shape, mu.shape)                         # torch.Size([8, 784]) torch.Size([8, 16])
print(loss.item() > 0, kl.item() >= 0)                # True True

new_images = torch.sigmoid(vae.dec(torch.randn(4, 16)))   # generate: decode samples from the prior
print(new_images.shape)                               # torch.Size([4, 784])

Key point

The two terms pull against each other: reconstruction wants distinct, precise codes; KL wants everything to look like N(0, 1). That's why VAE samples tend to be slightly blurry — and why β-VAE adds a weight on the KL term to trade one for the other.

Autoencoder vs VAE?

An autoencoder maps each input to a single point and is trained only to reconstruct — good for compression and anomaly detection, but its latent space has holes. A VAE maps each input to a distribution and adds a KL penalty toward N(0, I), giving a continuous latent space you can sample from to generate new data.

What is the reparameterization trick?

Writing a sample as z = μ + σ·ε with ε drawn from a fixed N(0, 1). The random draw no longer depends on the parameters, so backpropagation can compute gradients with respect to μ and σ.

GANs

A generative adversarial network trains two networks against each other: a generator that turns random noise into fake samples, and a discriminator that tries to tell fakes from real data. Each improves by beating the other.

On a batch of real data (label 1) and generated data (label 0): ordinary binary classification.

A GAN in 1-D

Real data: numbers drawn from N(4, 1.25²). The generator starts out producing values near 0 and must learn to imitate them.

Python
import torch
from torch import nn

torch.manual_seed(0)
real_data = lambda n: torch.randn(n, 1) * 1.25 + 4.0

G = nn.Sequential(nn.Linear(1, 16), nn.ReLU(), nn.Linear(16, 1))                # noise → sample
D = nn.Sequential(nn.Linear(1, 16), nn.LeakyReLU(0.2), nn.Linear(16, 1))        # sample → real/fake logit
opt_g = torch.optim.Adam(G.parameters(), lr=1e-3, betas=(0.5, 0.999))
opt_d = torch.optim.Adam(D.parameters(), lr=1e-3, betas=(0.5, 0.999))
bce = nn.BCEWithLogitsLoss()
ones, zeros = torch.ones(64, 1), torch.zeros(64, 1)

with torch.no_grad():
    print(round(G(torch.randn(10000, 1)).mean().item(), 1))    # 0.0 ← before training

for step in range(3000):
    real, fake = real_data(64), G(torch.randn(64, 1))
    loss_d = bce(D(real), ones) + bce(D(fake.detach()), zeros)   # detach: don't update G here
    opt_d.zero_grad(); loss_d.backward(); opt_d.step()

    loss_g = bce(D(fake), ones)                                  # G wants D to say "real"
    opt_g.zero_grad(); loss_g.backward(); opt_g.step()

with torch.no_grad():
    samples = G(torch.randn(10000, 1))
print(round(samples.mean().item(), 1), round(samples.std().item(), 1))   # 4.0 0.5 ← mean learned; spread too narrow

The generator found the right centre but its samples are too concentrated (std 0.5 instead of 1.25) — a mild form of mode collapse: producing a narrow slice of plausible outputs is enough to fool this discriminator. Real GANs need care to avoid it.

How does a GAN work?

Two networks play a minimax game. The generator maps random noise to samples; the discriminator classifies samples as real or generated. The discriminator is trained to classify correctly, the generator to make the discriminator wrong. Over training, generated samples become harder to distinguish from real data.

What is mode collapse?

The generator learns to produce only a small variety of outputs (one kind of face, one digit) because those reliably fool the discriminator, ignoring the rest of the data distribution.

Diffusion Models

A diffusion model learns to reverse a gradual noising process. Training: add noise to real data and teach a network to predict that noise. Generation: start from pure noise and remove it step by step. It's the engine behind Stable Diffusion, DALL·E 3 and most image and video generators.

The forward (noising) process

Each step mixes in a little Gaussian noise according to a schedule β₁ … β_T. Conveniently, you can jump straight to any step t in closed form — no need to loop:

x_t = √ᾱ_t · x₀ + √(1 − ᾱ_t) · ε ε ~ N(0, I), ᾱ_t = Π (1 − β_s)
Python
import numpy as np

T = 1000
betas = np.linspace(1e-4, 0.02, T)          # the original DDPM linear schedule
alpha_bar = np.cumprod(1 - betas)

for_steps = {t: round(float(np.sqrt(alpha_bar[t])), 3) for t in (0, 250, 500, 999)}
print(for_steps)          # {0: 1.0, 250: 0.722, 500: 0.279, 999: 0.006} ← how much of the original signal remains

x0 = np.array([1.0, -1.0, 0.5])

Training: predict the noise
loss = ‖ ε − ε_θ(x_t, t) ‖² (t random, ε random, x₀ from the data)

That's the whole objective: a plain mean-squared error. The network (a U-Net or a Transformer — “DiT”) takes the noisy input and the step t, and guesses the noise that was added. A toy version on 1-D data — a mixture of two bumps at −2 and +2:

Python
import torch
from torch import nn

torch.manual_seed(0)
T = 100
betas = torch.linspace(1e-4, 0.1, T)
alphas, alpha_bar = 1 - betas, torch.cumprod(1 - betas, dim=0)
data = lambda n: torch.where(torch.rand(n, 1) < 0.5, -2.0, 2.0) + 0.3 * torch.randn(n, 1)

model = nn.Sequential(nn.Linear(2, 64), nn.SiLU(), nn.Linear(64, 64), nn.SiLU(), nn.Linear(64, 1))
opt = torch.optim.Adam(model.parameters(), lr=2e-3)

for step in range(3000):                                      # training
    x0 = data(256)
    t = torch.randint(0, T, (256, 1))
    eps = torch.randn_like(x0)
    xt = alpha_bar[t].sqrt() * x0 + (1 - alpha_bar[t]).sqrt() * eps   # jump to step t
    loss = ((model(torch.cat([xt, t / T], dim=1)) - eps) ** 2).mean()
    opt.zero_grad(); loss.backward(); opt.step()

with torch.no_grad():                                         # sampling (DDPM)
    x = torch.randn(2000, 1)                                  # start from pure noise
    for t in reversed(range(T)):
        eps_hat = model(torch.cat([x, torch.full_like(x, t / T)], dim=1))
        x = (x - betas[t] / (1 - alpha_bar[t]).sqrt() * eps_hat) / alphas[t].sqrt()
        if t > 0:
            x = x + betas[t].sqrt() * torch.randn_like(x)     # a little fresh noise each step

print(round(alpha_bar[-1].item(), 3))                         # 0.006 ← x_T is essentially pure noise
print(round((x < 0).float().mean().item(), 2))                # 0.49 ← about half the samples in each bump
print(round(x[x < 0].mean().item(), 1), round(x[x > 0].mean().item(), 1))   # -2.0 2.0 ← centred on the two modes

Key point

The GenAI notes (Diffusion & GANs) cover these models from the product side; the key mechanical idea is simply: learn to denoise at every noise level, then chain the denoising steps.

How do diffusion models generate images?

They're trained to predict the noise added to real images at random noise levels. To generate, start from pure Gaussian noise and repeatedly subtract the predicted noise (plus a little fresh noise), moving from step T to 0 until a clean image remains; text prompts steer each step through cross-attention and classifier-free guidance.

Why did diffusion models overtake GANs for image generation?

Their training objective is a stable regression loss (no adversarial game), they cover the data distribution without mode collapse, and they scale well with data and compute. The main drawback — slow multi-step sampling — was largely solved by better samplers, latent diffusion and distillation.

Interview Prep

Interview Questions

Deep learning questions that come up in ML engineer and data scientist interviews — short answers you can say out loud, with pointers to the topic that explains each one.

Fundamentals
What is the difference between machine learning and deep learning?

Deep learning is a subset of ML that uses many-layered neural networks to learn features directly from raw data. Classic ML relies on hand-engineered features and shines on small/tabular data; deep learning shines on images, audio and text, and when data and compute are plentiful.

Why do neural networks need activation functions?

Without non-linearities, stacked linear layers collapse into a single linear map. Activations like ReLU let the network represent non-linear functions. (See Activation Functions.)

What does the universal approximation theorem say — and not say?

A single hidden layer with enough units can approximate any continuous function on a bounded domain. It doesn't say how many units, whether gradient descent will find the weights, or whether the result will generalise; depth is far more efficient in practice.

How many parameters does a Conv2d(64, 128, kernel_size=3) have?

128 × (64 × 3 × 3) + 128 = 73,856. Parameters don't depend on the image size.

Training
Explain backpropagation.

Run a forward pass storing intermediate values, then apply the chain rule from the loss backwards: each operation multiplies the incoming gradient by its local derivative and passes it on. One backward pass yields gradients for all parameters at roughly twice the cost of a forward pass.

Batch vs mini-batch vs stochastic gradient descent?

Batch uses the whole dataset per step (exact but slow), SGD one example (cheap but noisy), mini-batch a few dozen to a few thousand (the practical default: GPU-efficient with useful noise).

How does Adam work? Why AdamW?

Adam keeps an exponential average of gradients (momentum) and of squared gradients (per-parameter scale), with bias correction, and steps by m̂ / (√v̂ + ε). AdamW applies weight decay directly to the weights instead of through the gradient, so regularisation isn't distorted by the adaptive scaling.

What happens if the learning rate is too high or too low?

Too high: the loss oscillates, diverges or becomes nan. Too low: training crawls and may stall on plateaus. Use an LR range test, warmup and a decay schedule (cosine is a good default).

Why use cross-entropy loss for classification, and what should the initial loss be?

It's the negative log-likelihood of the correct class and gives strong gradients (p − y) when the model is confidently wrong. With k balanced classes and a fresh model, expect about ln k (2.30 for 10 classes).

Stability & generalisation
What causes vanishing/exploding gradients and how do you fix them?

Gradients are products of per-layer factors; below 1 they shrink exponentially, above 1 they blow up. Fixes: ReLU-family activations, He/Xavier init, BatchNorm/LayerNorm, residual connections, gradient clipping, LSTM/GRU for sequences.

How does batch normalization behave differently at train and test time?

In training it normalises with the current batch's mean/variance and updates running averages; in eval mode it uses those running averages. Forgetting model.eval() is a common bug.

How does dropout work?

In training each unit is zeroed with probability p and survivors are scaled by 1/(1−p); at test time it's off. It prevents co-adaptation and acts like an ensemble of sub-networks.

Your training accuracy is 99% but validation is 75%. What do you do?

Overfitting: add data or augmentation, weight decay, dropout, early stopping, a smaller or pretrained model. Also check for distribution mismatch or leakage between splits.

Your training loss is not decreasing. How do you debug?

Verify data and labels, check the initial loss (≈ ln k), try to overfit a tiny batch, then look for bugs — missing zero_grad, softmax before CrossEntropyLoss, wrong shapes/dtypes, frozen parameters, bad LR. Inspect gradient norms per layer.

Architectures
Why do CNNs work well for images?

Local receptive fields, weight sharing and pooling exploit spatial structure: far fewer parameters than dense layers, translation equivariance, and a hierarchy from edges to objects.

What problem do residual connections solve?

Very deep plain networks trained worse than shallower ones (degradation). Skip connections y = F(x) + x give gradients an identity path and make identity mappings easy, enabling 100+ layer networks. Transformers use them in every block.

RNN vs LSTM vs Transformer?

RNNs process sequences step by step and struggle with long-range dependencies (vanishing gradients). LSTMs add gates and an additive cell state to remember longer. Transformers use self-attention: any two positions interact directly and training is parallel — at O(n²) cost in sequence length.

Explain scaled dot-product attention. Why the scaling?

softmax(QKᵀ/√d_k)V: each query scores every key, softmax turns scores into weights, and the output is the weighted sum of values. Dot products grow like √d_k; without scaling, softmax saturates and gradients vanish.

Encoder-only vs decoder-only Transformers?

Encoder-only (BERT) uses bidirectional attention and suits understanding tasks — classification, embeddings. Decoder-only (GPT-style LLMs) uses causal attention and is trained to predict the next token — generation. Encoder–decoder (T5) maps one sequence to another.

When would you use transfer learning?

Almost always when a relevant pretrained model exists and your labelled data is limited: replace the head, train it with the backbone frozen, then optionally fine-tune deeper layers with a small learning rate.

Generative models
Compare VAEs, GANs and diffusion models.

VAEs: encoder–decoder with a KL-regularised latent space; stable, but samples are blurry. GANs: generator vs discriminator; sharp samples, unstable training and mode collapse. Diffusion: learn to denoise at every noise level, sample by iterative denoising; high quality and diversity, stable training, slower sampling.

What is the reparameterization trick in VAEs?

Sampling z = μ + σ·ε with ε ~ N(0, 1) moves the randomness outside the network, so gradients can flow through μ and σ.

Practical
What's the difference between model.eval() and torch.no_grad()?

model.eval() changes layer behaviour (dropout off, BatchNorm uses running stats). torch.no_grad() stops gradient tracking to save memory and time. For inference you want both.

How do you train with a batch that doesn't fit in GPU memory?

Gradient accumulation (several micro-batches, divide the loss, step once), mixed precision (bf16/fp16), gradient checkpointing, a smaller model, or sharding across GPUs (FSDP).

What is mixed precision training?

Computing in 16-bit floats with 32-bit master weights to cut memory and speed up tensor-core math; float16 needs a gradient scaler to avoid underflow, bfloat16 usually doesn't.
